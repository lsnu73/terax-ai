# 通知中心

- 最后校验：2026-11-03
- 状态：已覆盖

## 业务需求

顶栏铃铛统一展示编码代理活动和软件运行消息。用户既能立即看到应用内消息，也能只接收未读角标，打开通知后再查看标题、详细错误和可用操作。代理软件启动失败等错误需要保留原始系统原因，不能只留在开发者控制台。

## 入口与调用链

- 通知入口：`src/modules/header/Header.tsx` 渲染 `src/modules/agents/components/NotificationBell.tsx`；铃铛读取 `src/modules/agents/store/agentStore.ts` 中的活跃 Agent 与通知历史。
- 软件消息：各业务模块调用 `src/modules/agents/lib/runtimeNotifications.ts` 的 `runtimeToast` → `pushNotification` 写入历史 → 根据 `notificationDisplayMode` 决定调用 Sonner 或只保留未读角标。
- Agent 消息：`AgentNotificationsBridge` / `LocalAgentNotificationsBridge` → `src/modules/agents/lib/route.ts:routeAgentNotification` → 同一通知 store；应用内 toast 同样遵循显示方式，窗口未聚焦时仍使用系统原生通知。
- 代理启动失败：`src/modules/proxy/lib/autoLaunch.ts:ensureProxySoftwareRunning` 捕获 `proxy_ensure_running` rejection，保留控制台日志并发送 error 级 `runtimeToast`，正文为原始 Rust/OS 错误。
- 显示方式设置：`src/settings/sections/GeneralSection.tsx` → `setNotificationDisplayMode`（`src/modules/settings/store.ts`）→ 偏好广播 → 主窗口内存 store 更新。

## 数据流 / 关键流程

1. 软件消息先保存标题、正文、级别和可选动作，再按偏好决定是否在应用内弹出，badge 模式不会丢失历史。
2. 带稳定 ID 的消息更新原记录并重新标为未读，不重复堆叠；dismiss 同时移除对应历史。
3. 更新前后的 Sonner 与通知中心共享关闭状态，程序关闭、用户关闭和清空通知交错时，原 `onDismiss` 只执行一次。
4. 打开通知弹层调用 `markAllRead`；Agent 项跳转到对应会话。运行时项的主体是可键盘激活的按钮，点击后保持原弹层打开，并在消息列表右侧紧贴显示详情栏；左右栏使用完整圆角且高度各自独立，详情栏垂直中心与所选消息中心对齐，左侧列表高度不随详情正文拉伸。完整标题不截断，正文保留换行并可滚动查看。
5. 详情栏的复制按钮写入完整标题与正文并显示已复制反馈；正文与底部操作区之间无分割线。关闭详情栏不移除通知。在列表或详情中执行动作/取消仍复用 `runNotificationAction`，执行后 dismiss 对应消息；通知被外部清除时详情同步关闭。

## 对外接口

- 前端接口：`runtimeToast` 的 message/success/info/warning/error/dismiss 方法，类型见 `src/modules/agents/lib/runtimeNotifications.ts`。
- 偏好：`notificationDisplayMode: "toast" | "badge"`，存于 **terax-settings.json**。
- 无新增 Rust 命令或 Tauri 事件。

## 已知限制

- 通知与未读状态仅保留在当前进程内，重启后清空，最多保留 50 条。
- 只有显式调用 `runtimeToast` 或 Agent 路由的消息进入通知中心；普通 `console.warn/error` 和 Rust 日志不会自动转换为用户通知。
- badge 模式只抑制应用内弹出消息，不关闭 Agent 的系统原生通知和声音策略。
