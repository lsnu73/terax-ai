## 1. 业务需求

侧边栏「源代码管理」视图（Git 页面）让用户在不离开终端工作区的情况下完成日常 Git 操作：查看变更文件、暂存/撤销、提交、与远程同步。仓库目标可以跟随当前工作上下文（终端 cwd、活动 tab），也可以固定到某个仓库。头部提供从远程获取、拉取（ff-only）与刷新按钮，底部提供提交与推送按钮。

远程操作（获取、拉取、推送）失败时，错误以通知（toast + 通知铃铛）展示，不占用按钮周围的面板空间；footer 只保留提交流程的反馈。推送要考虑用户的 SSH key 是加密的情况：git 在 Terax 内无 TTY 可提示，加密 key 会被 ssh 静默跳过并报 `Permission denied (publickey)`，此时面板弹出密码对话框，用户输入 SSH key 密码后带密码重试推送；密码仅本次使用，不落盘、不进命令行参数。

- 远程操作：fetch/pull/push 按钮在 `src/modules/source-control/SourceControlPanel.tsx:746` 起的一行；推送按钮在 `:990`。`src/modules/source-control/useSourceControlPanel.ts:936` 的 `push` 首次失败且命中 SSH 鉴权错误时弹出 `SshPassphraseDialog`（`src/modules/source-control/SshPassphraseDialog.tsx:28`），`:958` 的 `submitSshPassphrase` 带密码重试。
- Tauri 侧：`git_fetch` / `git_pull_ff_only` / `git_push`（`src-tauri/src/modules/git/commands.rs:184`）→ `operations::push`（`src-tauri/src/modules/git/operations.rs:471`）→ 加密码时 `src-tauri/src/modules/git/askpass.rs:34` 的 `SshAskpass::create` 写临时 askpass 脚本，`src-tauri/src/modules/git/process.rs:259` 的 `run_git_with_env` 注入 `SSH_ASKPASS` / `SSH_ASKPASS_REQUIRE=force` / `DISPLAY` / `TERAX_SSH_PASSPHRASE`。
- 失败通知：`useSourceControl` 的 `runRemoteAction` 与自动 fetch 失败路径发 `runtimeToast.error`（后台自动 fetch 按仓库+错误消息去重，成功后重置）。

```text
推送按钮 -> useSourceControlPanel.push -> runRemoteAction("push")
  -> native.gitPush -> git_push (Tauri) -> operations::push
  失败且 SSH 鉴权 -> SshPassphraseDialog -> submitSshPassphrase
  -> runRemoteAction("push", { passphrase }) -> SshAskpass + run_git_with_env
```

## 4. 数据流 / 关键流程

1. `useSourceControlContext` 汇聚活动 tab、终端 cwd、侧栏可见性，`statusConsumers` 判定是否有 live 消费者；`planContextRefresh` 决定是否运行 `git status`，有上游且距上次自动 fetch 超 5 分钟时顺带 fetch。
2. 显式 fetch/pull/push 走 `runRemoteAction`：成功后清 `lastRemoteError` 并刷新状态；失败把错误写入 `lastRemoteError`（仅作状态保留）并发通知。
3. 推送失败且错误形如 `Permission denied (publickey)` / `incorrect passphrase`（ssh 无 TTY 时加密 key 被静默跳过的产物）→ 弹出 `SshPassphraseDialog`；提交密码后 Rust 侧写临时 askpass 脚本重试，`WSLENV`（`SSH_ASKPASS/up` 等 token）把脚本路径与密码转发进 WSL 发行版。
4. footer 的 `footerFeedback` 只反映 `actionError`/`actionMessage`（提交流程）；远程失败一律走通知。

## 5. 对外接口

- Tauri 命令：`git_fetch`、`git_pull_ff_only`、`git_push`（`git_push` 的 `passphrase` 参数为可选）——契约见 `src-tauri/src/modules/git/commands.rs` 与 `src/modules/ai/lib/native.ts` 的 `native.gitFetch/gitPullFfOnly/gitPush`。
- `useSourceControl` 返回 `SourceControlSummary`（status/ahead/behind/busyAction/`runRemoteAction(mode, options?)` 等），供面板、git tab、资源管理器装饰与 rail 徽标消费。
- 无持久化格式变更；SSH 密码只在内存与 askpass 子进程环境变量中存在一次推送周期。

## 6. 配置与依赖

- 依赖系统 `git`（本地或 WSL 发行版内），可用性校验与版本下限见 `src-tauri/src/modules/git/process.rs` 的 `ensure_git_available`。
- SSH 推送解锁依赖 OpenSSH ≥ 8.4 的 `SSH_ASKPASS_REQUIRE=force`（Git for Windows 自带 ssh 已满足）；`DISPLAY` 兜底旧版本行为。
- askpass 脚本位于系统临时目录，文件名前缀 `terax-askpass-<进程号>-<序号>`，扩展名按平台为 `.cmd` 或 `.sh`。

## 7. 已知限制与注意事项

- `Permission denied (publickey)` 也可能是 key 未在远端注册：此时密码对话框帮不上忙，取消后错误仍以通知展示。根因与报错不可区分性见[关联坑点](../../lore/pitfalls/2026-11-15-无TTY下加密SSH key被静默跳过.md)。
- HTTPS 远程的凭据失败（`could not read username`）不会触发密码对话框，只会通知——本对话框只服务 SSH key 解锁。
- WSL 仓库的 askpass 链路（WSLENV 转发 + `/mnt` 路径翻译）按既有模式实现，尚未构造 WSL 加密 key 场景端到端验证。
- 推送固定使用上游分支（`operations::push` 走 `git push`），不提供推送参数；diverged（ahead+behind）时推送按钮被禁用。
