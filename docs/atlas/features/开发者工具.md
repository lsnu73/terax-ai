## 1. 业务需求

用户需要在软件主界面打开 WebView 的浏览器开发者控制台，用于检查页面结构、样式、网络请求和前端日志。设置页和 AI 面板过去能打开控制台，但主界面不能，发行版也缺少 WebView DevTools 支持。成功标准是开发版和发行版都能从主窗口主动打开 DevTools。

## 2. 入口与调用链

- 快捷键声明：`src/modules/shortcuts/shortcuts.ts:109` 注册 `devtools.open`。
- 键盘入口：`src/modules/shortcuts/lib/useGlobalShortcuts.ts:28` 在 window 捕获阶段分发快捷键。
- 应用处理器：`src/app/App.tsx:893` 调用 Tauri `open_devtools` 命令。
- 原生命令：`src-tauri/src/lib.rs:85` 的 `open_devtools`，在 `src-tauri/src/lib.rs:348` 注册。
- 发行版能力：`src-tauri/Cargo.toml:40` 的 Tauri `devtools` feature。

调用链：

```text
Mod+Alt+I 或 F12
  -> useGlobalShortcuts
  -> App.shortcutHandlers["devtools.open"]
  -> invoke("open_devtools")
  -> Rust open_devtools(window)
  -> window.open_devtools()
```

## 4. 数据流与关键流程

1. 用户按键后，快捷键注册表按用户覆盖或默认绑定匹配 `devtools.open`。
2. 匹配成功时全局监听器阻止浏览器默认行为，并调用应用层处理器。
3. 前端使用 `invoke("open_devtools")` 请求 Rust 侧打开当前 webview 的 DevTools。
4. Rust 命令注入调用方 `WebviewWindow`，直接对同一 webview 调用 `open_devtools()`。
5. Tauri `devtools` feature 让该 API 在 release 构建中仍可用。

## 5. 对外接口

- 用户接口：快捷键设置页中的「打开开发者工具」，ID 为 `devtools.open`。
- Tauri 命令：`open_devtools`，无参数，作用于调用方 webview。
- HTTP、事件与第三方接口：无。

## 6. 配置与依赖

- 默认绑定：macOS 为 `Mod+Alt+I`，Windows 与 Linux 为 `Ctrl+Alt+I`；另有 `F12`。
- 编译能力：Tauri `devtools` feature。
- 与 AI 窗口的关系：`ai.toggle` 使用 `Mod+I`，与开发者工具的 `Mod+Alt+I` 和 `F12` 分离。
- 与设置窗口的关系：设置窗口未挂载全局快捷键，仍可使用 WebView 原生调试快捷键；发行版可用的前提同样是 `devtools` feature。

## 7. 已知限制与注意事项

- 没有为 DevTools 本身增加自动化测试。实际打开行为通过运行中的应用和窗口标题验证。
- Windows 的 Tauri API 文档将关闭和查询 DevTools 标记为不支持的平台能力，因此实现只调用打开，不依赖关闭或查询。
- 发行版开放 DevTools 是明确的产品选择，设计与安全取舍见关联 lore 决策。
- 若用户清空快捷键或改键，按钮分发路径不变，仅匹配条件变化。
