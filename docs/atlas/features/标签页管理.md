# 标签页管理

- 最后校验：2026-11-02（`terax-diy`）
- 状态：已覆盖
- 关联坑点：[终端指针事件约束](../../lore/pitfalls/2026-10-28-pointer-vs-mouse-events.md)

## 1. 业务需求

主窗口顶部标签栏用于新建、切换、排序和关闭终端、编辑器、预览及 Git 等标签。终端标签支持重命名和刷新，所有标签提供关闭右侧、关闭其他等右键操作。菜单打开后，点击任意菜单外区域或按 Escape 都应关闭菜单，菜单内部操作保持可用。

## 2. 入口与调用链

- 入口：`src/modules/header/Header.tsx:181` 渲染 `TabBar`，将 App 协调层传入的标签状态和操作回调接入标签栏。
- 标签状态：`src/modules/tabs/lib/useTabs.ts:582` 的 `useTabs` 维护标签列表、活动标签、关闭与排序等状态。
- 标签 UI：`src/modules/tabs/TabBar.tsx:93` 渲染标签、活动指示、拖拽排序、关闭按钮和右键菜单。
- 新建入口：`src/modules/tabs/NewTabMenu.tsx:43` 提供终端、隐私终端、编辑器、预览、Git 图和编码代理启动入口。
- 菜单关闭：`src/modules/tabs/TabBar.tsx:143` 在菜单打开期间监听 document 捕获阶段 `pointerdown`；`src/modules/tabs/TabBar.tsx:547` 通过 `contextMenuTabId` 控制当前菜单。

## 4. 数据流与关键流程

1. `useTabs` 提供标签列表和活动 ID，App 协调业务操作，Header 将其传给 `TabBar`。
2. 用户右键标签时，`ContextMenu.onOpenChange` 记录该标签 ID；同一时间只打开一个标签菜单。
3. 菜单打开期间，document 捕获阶段先检查指针目标。目标不在当前 `ContextMenuContent` 内时清空菜单状态，事件继续按原路径传播。
4. 点击菜单项或按 Escape 仍由 Radix 触发 `onOpenChange`，保留原有菜单选择与焦点行为。

```text
右键标签 -> contextMenuTabId = tab.id -> 打开对应菜单
菜单外 pointerdown（捕获） -> contextMenuTabId = null -> 关闭菜单
菜单内 pointerdown -> 不处理 -> 菜单项正常选择
```

## 5. 对外接口

- `TabBar` 接收标签列表、活动 ID 以及新建、选择、关闭、重命名、刷新和排序回调，具体类型见 `src/modules/tabs/TabBar.tsx`。
- 无新增 Tauri command、持久化字段或网络接口。

## 6. 配置与依赖

- UI 使用现有 Radix `ContextMenu` 和 shadcn/ui 封装，无新增依赖。
- 捕获监听只在菜单打开期间存在，关闭后立即移除。

## 7. 已知限制与注意事项

- 终端选区控制器会阻止指针事件冒泡，因此不能只依赖 Radix 的冒泡阶段外部关闭监听，也不能通过 `onPointerDownOutside` 单独解决。
- 当前没有标签菜单的 DOM 组件测试设施，修改后需手工覆盖终端、编辑器、空白区域、菜单内部、Escape 和连续右键路径。
