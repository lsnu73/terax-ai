# 终端输入法候选框定位

- 最后校验：2026-11-03（`terax-diy`，工作区含本轮未提交改动）
- 状态：开发中
- 关联 lore：暂无

## 1. 业务需求

在终端里用中文、日文等输入法打字时，输入法候选窗应出现在终端光标所在位置（跟随光标），而不是固定在窗格左上角。成功标准：光标移动后（回车、方向键、新命令行），下一轮输入的候选窗出现在新光标处。

## 2. 入口与调用链

原理：终端是自绘网格（WebGPU/WebGL），真正的输入接收者是隐藏的 `<textarea>`（输入代理）。WebView 的输入法候选窗锚定在这个 textarea 的插入符处，因此**textarea 的元素位置就是候选窗位置**。

- textarea 创建：`src/modules/terminal/ghostty/gpu/WebGpuTerminalSurface.ts:138`、`src/modules/terminal/ghostty/webgl/WebGlTerminalSurface.ts:97`（`position:absolute;left:0;top:0;width:1px;height:1px;opacity:0`）
- 定位同步：每帧渲染时调用 `syncInputCaret`（`WebGpuTerminalSurface.ts:473`、`WebGlTerminalSurface.ts:400`），把元素移到 `cursor.x * cellWidth, cursor.y * cellHeight`（CSS 像素），并叠加 `gridShiftY()`。
- 调用点：WebGPU 在 `prepareFrame`（`WebGpuTerminalSurface.ts:652`，`model.cursor()` 之后）；WebGL 在 `renderFrame`（`WebGlTerminalSurface.ts:471`）。

## 3. 涉及文件

| 文件 | 角色 | 备注 |
|---|---|---|
| `src/modules/terminal/ghostty/gpu/WebGpuTerminalSurface.ts` | WebGPU surface | 持有 textarea，`syncInputCaret` 每帧同步位置 |
| `src/modules/terminal/ghostty/webgl/WebGlTerminalSurface.ts` | WebGL 回退 surface | 与 WebGPU 行为一致 |
| `src/modules/terminal/ghostty/input/GhosttyInputController.ts` | 输入事件控制器 | 消费 textarea 的 keydown/composition 事件（不负责定位） |
| `src/modules/terminal/ghostty/input/TerminalInputProxy.ts` | 输入代理状态机 | 维护占位符与选区，不移动元素 |

## 4. 数据流 / 关键流程

1. 模型输出 damage → surface 的运行时调度一帧；
2. `prepareFrame` / `renderFrame` 取 `model.cursor()`（坐标为视口相对行/列，与着色器画的光标矩形同一坐标系，滚动回历史时可能超出 `0..rows-1`）；
3. `syncInputCaret` 把坐标钳制到网格内，换算成 CSS 像素写入 textarea 的 `left/top`；
4. WebView 把输入法候选窗锚到 textarea 新位置。

组合输入（composition）进行中终端光标不会前移（文本未提交），因此不会在打字中途跳动。

## 5. 对外接口

无（纯窗口内交互行为）。

## 6. 配置与依赖

无独立配置。依赖 `model.cursor()`、`model.cols/rows`、`cellSize()` 与 `gridShiftY()`。

## 7. 已知限制与注意事项

- 候选窗跟随的是元素左上角（1×1 像素），精度到单元格，不到字形内插入点。
- 向上翻阅历史时真实光标不在屏幕上，候选窗钳制在网格边缘。
- 首帧渲染前 textarea 仍在左上角（挂载后立即出帧，实际不可感知）。
- 若未来把 textarea 改回固定位置或改成单例共享，必须保留「跟随光标」的同步逻辑，否则输入法候选窗退回左上角。
