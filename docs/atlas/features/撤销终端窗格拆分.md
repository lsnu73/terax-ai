# 撤销终端窗格拆分

- 状态：开发中

## 1. 业务需求

用户在终端标签页中拆分窗格后，可以撤销最近一次拆分，关闭该次拆分新建的窗格，并回到拆分前活动的窗格。成功标准是窗格树恢复少一个新叶节点、原活动窗格重新获得焦点，且被关闭窗格的终端资源得到释放。

默认入口为 macOS 的 Cmd+Shift+Z，其他平台的 Ctrl+Shift+Z。用户可以在设置的快捷键页面覆盖该绑定。

## 2. 入口与调用链

- 键位声明：`src/modules/shortcuts/shortcuts.ts:162` 注册 `pane.undoSplit`，默认绑定为 Mod+Shift+Z。
- 键盘入口：`src/modules/shortcuts/lib/useGlobalShortcuts.ts:28` 在 window 捕获阶段匹配快捷键。
- 应用处理器：`src/app/App.tsx:914` 将当前活动标签页 ID 传给 `undoLastSplit`。
- 作用域检查：`src/app/App.tsx:989` 在非终端标签页禁用该处理器，并继续检查其他匹配快捷键。
- 核心流程：`src/modules/tabs/lib/useTabs.ts:1307` 的 `undoLastSplit`。
- 树转换：`src/modules/terminal/lib/panes.ts:118` 的 `removeLeaf` 删除叶节点并折叠只剩一个子节点的 split。
- 资源清理：`src/modules/terminal/lib/terminalSessionApi.ts:69` 的 `disposeSession` 释放终端模型、命令块和展示状态。

完整调用链：

```text
Mod+Shift+Z
  -> useGlobalShortcuts.onKey
  -> App.shortcutHandlers["pane.undoSplit"]
  -> useTabs.undoLastSplit(tabId)
  -> removeLeaf(paneTree, newLeafId)
  -> disposeSession(newLeafId)
```

## 4. 数据流与关键流程

1. `splitActivePane`（`src/modules/tabs/lib/useTabs.ts:1273`）创建新叶节点，并按标签页记录 `newLeafId` 与 `previousActiveLeafId`。
2. 全局键盘监听器读取用户覆盖绑定或默认绑定，匹配成功后检查当前标签页是否允许执行。
3. `undoLastSplit` 取出该标签页最近一次拆分记录，确认新旧两个叶节点仍存在于当前树中。
4. `removeLeaf` 返回新的 PaneNode 树，`useTabs` 恢复先前活动叶节点及其 cwd。
5. 只有实际移除叶节点后才调用 `disposeSession`，随后函数返回是否撤销成功。

拆分历史保存在 `splitHistoryRef`（`src/modules/tabs/lib/useTabs.ts:596`），键为标签页 ID，值为按拆分顺序排列的内存数组。

## 6. 配置与依赖

- 用户偏好：`shortcuts` 中可选的 `pane.undoSplit` 绑定；未设置或重置后使用默认值。
- 状态依赖：当前活动 Tab、PaneNode 树、每标签页拆分历史。
- 生命周期依赖：`disposeSession` 必须与新叶节点移除配对执行。
- 环境变量与第三方服务：无。

## 7. 已知限制与注意事项

- 拆分历史只存在内存中，应用重载、工作区恢复或替换整组标签页后不能撤销此前拆分。
- 手动关闭窗格或交换窗格会清除相关标签页的拆分历史；没有有效历史时快捷键不执行操作。
- 撤销会关闭新建窗格及其终端会话，不提供重做，也不会恢复该会话中的进程状态。
- 截至校验日，未检索到 `undoLastSplit` 的专项自动化测试；通用 PaneNode 或快捷键测试不等同于完整链路覆盖。
