# 文件资源管理器

- 最后校验：2026-11-04

## 1. 业务需求

左侧侧边栏中的文件资源管理器提供按名称模糊搜索。搜索结果展示为裁剪后的目录树，只保留命中项及其祖先目录，不再把每个命中项平铺并重复显示相对路径。工具栏已经显示工作区根目录，结果树不重复生成根节点行，而是从根目录下的顶层命中目录或文件开始。多个命中共享目录时合并祖先分支，兄弟节点保持后端模糊排名顺序，不额外按名称排序。

结果树默认全部展开。目录可点击或通过键盘折叠，文件保持单击和 Enter 打开；已有右键菜单、终端定位、源代码管理、Git 历史、复制路径和附加到 AI 操作不变。

## 2. 入口与调用链

- 搜索入口：`src/modules/explorer/FileExplorer.tsx` 挂载 `ExplorerSearch`，搜索激活时隐藏普通文件树。
- 查询执行：`src/modules/explorer/ExplorerSearch.tsx` 对查询做 300 ms 防抖，至少两个字符后调用 `fs_search`，沿用隐藏文件偏好、工作区环境和 200 条命中上限。
- 树转换：`src/modules/explorer/lib/searchTree.ts` 的 `buildSearchTreeRows` 以 `rootPath` 作为内部路径基准，按 `hit.rel` 补齐祖先并输出带深度的先序可见行，不输出工作区根节点行。
- 展示与交互：`src/modules/explorer/ExplorerSearch.tsx:92` 派生 `treeRows`，统一用于渲染、上下键导航、Enter、左右键折叠和滚动定位。
- 路径复用：祖先绝对路径通过 `src/modules/explorer/lib/useFileTree.ts` 的 `joinPath` 生成，真实命中始终保留后端返回的 `path`。

```text
ExplorerSearch query
  -> fs_search(root, query, limit=200)
  -> SearchHit[]
  -> buildSearchTreeRows(rootPath, hits, collapsedPaths)
  -> 祖先目录 + 命中项的先序可见行（不含工作区根节点行）
  -> 文件打开 / 目录折叠 / 原有右键操作
```

## 4. 数据流与关键流程

1. 后端按完整相对路径进行模糊匹配，返回有排序的 `SearchHit[]`。
2. 前端以工作区根节点作为内部挂载点，按命中顺序逐段插入相对路径，已存在的祖先不重复插入。
3. 若后续真实目录命中对应已生成的祖先，则合并其真实路径和名称，不改变子节点顺序。
4. 从根节点的子节点开始先序遍历并生成可见行，遇到折叠目录时跳过其后代，因此工作区根目录不占用结果行。
5. 新查询、根目录或隐藏文件偏好变化时重置折叠状态；关闭搜索时清空结果与选中状态。

## 5. 对外接口

- `buildSearchTreeRows(rootPath, hits, collapsedPaths?)`：纯函数，返回 `SearchTreeRow[]`，不读取文件系统。
- `fs_search` 的请求与响应契约不变，无新增 Tauri command、HTTP 接口或持久化格式。

## 6. 已知限制与注意事项

- 搜索树只展示当前后端返回的命中及其祖先，命中达到上限时不会补全其余文件系统分支。
- 兄弟节点顺序继承模糊排名，因此不保证与普通文件树的字典序一致。
- 搜索目录折叠仅保存在组件本地，不触发目录读取，也不影响普通文件树展开状态。
- 普通文件树的创建、重命名、移动、拖放与 watcher 链路未在本次覆盖范围内展开。
