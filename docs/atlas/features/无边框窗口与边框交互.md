# 无边框窗口与边框交互

- 最后校验：2026-11-08
- 状态：已覆盖

## 1. 业务需求

Windows/Linux 使用无边框透明窗口，圆角、描边与窗口控制按钮由应用自绘（macOS 保留原生红绿灯，不参与本功能）。围绕这条自绘边框有三条需求：

- **最大化四角变直角**：非最大化时软件四角是 12px 圆弧；最大化后窗口铺满屏幕，圆弧与屏幕直角之间留下真空区域，点击会穿透到下层窗口。最大化时四角必须变为直角，还原窗口后恢复圆角。
- **窗口控制按钮点击区无真空**：每个按钮的可点击区域填满标题栏上下（40px 通栏高），按钮之间无缝隙，关闭按钮右缘与窗口右边框重合；图标维持原有大小不变。
- **左右边框拖动消歧**：拖动窗口左右边框时，用户可能想调整窗口宽度，也可能想打开/关闭/拖动侧栏（左：资源管理器侧栏；右：AI 面板）。规则：非最大化时只有「拖拽阀」（边框上垂直居中的一小段）执行侧栏操作，其余边框区域调整窗口宽度；最大化时窗口不可调整大小，整条左右边框统一执行侧栏操作。
- **收起态拖阀渐进展开**：侧栏收起时拖阀打开不再「拖过最小宽度才突然弹出」，而是拖动过程中面板宽度逐像素跟随（一点一点展开）；松手时拖动距离不足最小宽度则自动补齐到最小宽度，超过则宽度由拖动距离决定。

## 2. 入口与调用链

- chrome 标记：`src/main.tsx:15` 在非 macOS 平台给 `<html>` 打 `data-chrome="borderless"`，并调用 `src/lib/maximizedChrome.ts:29` 的 `trackMaximizedChrome()` 把最大化状态镜像到 `<html data-maximized>`；`src/lib/maximizedChrome.ts:41` 的 `useWindowMaximized()` 为 React 组件提供同一状态。
- 圆角绘制：`src/styles/globals.css:277` 给 `#root` 等根容器画 12px 圆角与描边；`src/styles/globals.css:293` 在 `[data-maximized]` 时圆角清零并去描边，`globals.css:299` 同步处理背景图层 `.terax-bg-surface`。
- 窗口控制按钮：`src/components/WindowControls.tsx:42` 容器（贴右缘、无间隙）、`:96` 按钮（`h-full w-11` 通栏，无圆角）；最大化/还原图标切换依赖 `useWindowMaximized()`。
- 边框拖拽阀：`src/app/components/WindowEdgeValves.tsx:64` 渲染左右两条 16px 深的边框感应带（仅非 macOS）：
  - 阀段（`EdgeStrip :90`，垂直居中 96px）：点击（无位移）开关相邻面板；拖动按光标位置应用宽度（`beginValveDrag :144`），换算时除以 `--app-zoom`（内容区在 `zoom-content` 缩放上下文内）；
  - 收起态拖动展开：面板库会把低于最小宽度的 resize 钳制回最小宽度（收起态则钳回 0），导致收起态拖阀全程无反馈。阀在 pointerdown 按相邻面板收起态分流——收起时先 `beginDragOpen`（把面板 `minSize` 临时降为 0 解除钳制），拖动中 `applyDragOpen` 逐像素跟随，松手 `endDragOpen` 恢复最小宽度并把不足最小宽度的拖动距离补齐到最小宽度（`src/app/components/WindowEdgeValves.tsx:45` 起的控制器契约，实现在 `src/app/App.tsx:537`/`:571`）；
  - 其余边框区域（仅相邻面板收起且非最大化时渲染）：`beginWindowResize :134` 调用 `getCurrentWindow().startResizeDragging("West"/"East")` 交给系统原生 resize；
  - 最大化时阀段通栏全高，整条边框执行侧栏操作（此时 tao 不再提供原生 resize 边框，事件全部进网页）。
- 控制器与挂载：`src/app/App.tsx:521`（`sidebarValve`）、`:557`（`aiPanelValve`，未配置模型时禁用并复用分隔线的「先配置模型」提示）、`:1907` 挂载在面板组旁的 `relative` 容器内；两个面板的 `minSize` 由 `sidebarLiveMinSize`/`aiPanelLiveMinSize` 状态驱动（`App.tsx:512`/`:514`），仅在收起态拖阀展开期间为 0。

```text
窗口 resize -> isMaximized() 重查 -> <html data-maximized> + React 状态
  -> globals.css 最大化直角；WindowControls 图标切换；WindowEdgeValves 通栏阀

左阀段 pointerdown -> 捕获指针 -> pointermove 换算宽度(/zoom)
  -> 侧栏展开态: sidebarRef.resize()/collapse()；点击(未拖) -> toggleSidebar
  -> 侧栏收起态: beginDragOpen(minSize->0) -> applyDragOpen 逐像素跟随
     -> 松手 endDragOpen(恢复 minSize；不足最小宽度补齐)
右阀段同构 -> aiPanelRef；未配置模型 -> 提示先配置模型
非阀边框区域 pointerdown -> startResizeDragging -> 系统模态 resize
```

## 4. 数据流 / 关键流程

1. 最大化状态有两条消费通道：CSS 读 `<html data-maximized>`（无需 React 渲染），组件读 `useWindowMaximized()`；来源都是 `isMaximized()` 在每次 resize 后的重查。
2. 阀拖动宽度不经过面板组的 `onLayoutChanged`：侧栏阀显式调 `persistSidebarWidth(width, true)` 落盘；AI 面板宽度/开关经其面板 `onResize` 回写，与快捷键共用 `aiPanelStore` 同一状态源。
3. 收起态渐进展开只在拖动手势期间解除最小宽度钳制（`minSize` 降为 0）：`endDragOpen` 先按目标宽度（拖动距离补齐到最小宽度）resize，再恢复 `minSize`，钳制重算时面板已满足约束，不会跳动；拖动中的中间宽度不落盘，只有松手后的最终宽度持久化。拖回边缘（px≈0）面板同步收回，反馈连续。
4. 非最大化时窗口最外圈约 4px（SM_CXFRAME）由 tao 的 `WM_NCHITTEST` 直接返回 resize 命中，网页收不到那几像素的事件；webview 侧的 `startResizeDragging` 感应带把 resize 区延伸到 16px。
5. 阀段悬停显示 4px 竖条握把（`bg-border`），是阀与普通边框区域的唯一视觉区分。
6. 最大化通栏阀会覆盖相邻面板最外 16px 的点击（含侧栏 Rail 左缘与 AI 面板右缘），这是「最大化整条边框执行侧栏操作」需求的直接结果。

## 5. 对外接口

- 无新增 IPC；`startResizeDragging` 为 Tauri core API（需 `core:window:allow-start-resize-dragging` 权限）。
- CSS 状态契约：`html[data-chrome="borderless"]`、`html[data-maximized]`（由 `src/lib/maximizedChrome.ts` 维护）。

## 6. 配置与依赖

- tao 0.37：非最大化无边框窗口的原生 resize 边框由 Windows `WM_NCHITTEST` 消息的 hit-test 提供（tao 事件循环分支），最大化时自动关闭。
- `USE_CUSTOM_WINDOW_CONTROLS`（`src/lib/platform.ts`）为总开关：非 macOS 且运行于 Tauri 时为真；macOS 不渲染窗口控制按钮与边框阀。

## 7. 已知限制与注意事项

- Linux 的 `startResizeDragging` 依赖 tao 的 GTK 实现，未在 Linux 环境验证 `?`。
- 非最大化时窗口最外圈约 4px 始终是原生 resize，阀的有效命中从其后开始；想要拖阀时须避开最外圈。
- 阀段与面板内置分隔线是两个入口（边框 vs 面板间 1px 分隔线），行为一致但视觉提示不同：内置分隔线悬停高亮，边框阀悬停显示竖条握把。
- 窗口控制按钮改为通栏矩形后不再有圆角悬停效果，悬停高亮为整格背景色。
- 设计缘由与硬约束在 lore：分流取舍见 [decisions/2026-11-08-无边框窗口边缘交互分流.md](../../lore/decisions/2026-11-08-无边框窗口边缘交互分流.md)；最大化直角约束见 lore `INV-018`、边缘与原生 resize 互补约束见 `INV-019`、minSize 硬钳制与阀生命周期配对约束见 `INV-020`（[invariants.md](../../lore/invariants.md)）；最大化四角穿透坑点见 [pitfalls/2026-11-08-最大化后四角点击穿透.md](../../lore/pitfalls/2026-11-08-最大化后四角点击穿透.md)，收起态渐进展开被钳制吞掉的坑点见 [pitfalls/2026-11-08-收起态拖阀展开被面板库最小宽度钳制吞掉.md](../../lore/pitfalls/2026-11-08-收起态拖阀展开被面板库最小宽度钳制吞掉.md)。
