## 1. 业务需求

普通、隐私、恢复和代理终端统一把用户命令及其执行结果呈现为块，不再存在独立的「命令块」标签类型。终端始终保持原生 Shell 提示符和直接输入：用户看到 PowerShell 等原生提示符并在其中输入，块只是叠加在命令和结果上的装饰与操作层。

用户右键命令、输出或块头区域时，可以重新运行、复制命令、复制输出、复制命令和输出、附加到 AI 对话，或在当前块中查找。重新运行的可用性只由块自身状态决定（不在运行中且命令来源完整），不按全局提示符模式门控——ConPTY 流可能丢失 OSC 133 D 标记使会话模式卡在 `running`，按模式门控会让重跑永久灰掉。块的视觉装饰只有块尾分隔线（失败时红色并附退出码），路径、时间、耗时与悬浮重跑按钮已按用户要求移除，重跑入口只在右键菜单。终端存在非空文本选区时，右键继续服务「问问 Terax」选区流程，不得同时打开块菜单。新建隐私终端默认使用 Ctrl/Cmd+Shift+T。Ctrl+R 保留给 Shell 自身的反向历史搜索，设置页不得把它保存为其他全局快捷键。

## 2. 入口与调用链

### 统一块会话

- PTY 初始化：`src/modules/terminal/ghostty/useGhosttyTerminalSession.ts` 始终调用 `ensureGhosttyBlocks(leafId)`，并以 `blocks=true` 打开 PTY。
- Shell 集成：`src-tauri/src/modules/pty/scripts/` 下的 zsh、bash、fish、PowerShell 脚本始终发出 OSC 133 A/B/C/D；`TERAX_BLOCKS=1` 只在提示符上方预留块头间隔空行，不隐藏提示符。
- 标签状态：`src/modules/tabs/lib/useTabs.ts` 的 `TerminalTab` 不再有 `blocks` 标志或 `newBlockTab`。
- 工作区恢复：`src/modules/spaces/lib/serialize.ts` 不序列化独立块标签标志，旧 JSON 的多余字段自然忽略。
- 原生输入：终端输入元素始终把按键、组合文本和粘贴直通 PTY，块模式不再接管或丢弃输入。

### 块右键菜单

- 事件分流：`src/modules/terminal/TerminalPane.tsx` 的 `onContextMenuCapture`。
- 坐标换算：右键 `clientY` 经 `ghosttyBlockGeometry` 转为 viewport row，再由 `model.bufferLineAtViewportRow` 转为 buffer line。
- 块命中：`src/modules/terminal/ghostty/GhosttyBlocks.ts` 的 `blockAtLine` 根据 OSC 133 tracked pins 和块范围返回 `PositionedBlock`，运行中块的命中范围同样向上覆盖命令行。
- 菜单操作：`src/modules/terminal/block/BlockContextMenu.tsx` 提供六项操作。
- 菜单关闭：终端画布会吞掉 pointer 事件使 Radix 的外部点击失效，`TerminalPane` 在 `onPointerDownCapture` 捕获阶段主动关闭打开的块菜单。
- 块搜索：`TerminalPane` 为命中块创建 `GhosttyBlockSearchController`，经 `WorkspaceSurface` / `TerminalStack` 上报给 `App`，由 Ctrl+F 同一个 `SearchInline` 弹窗承载。

### 共享搜索弹窗

- Ctrl+F：`src/app/App.tsx` 的 `searchTarget` 使用活动叶节点的全文 `TerminalSearchController`，调用 `src/modules/header/SearchInline.tsx` 打开弹窗。
- 块内查找：`TerminalPane` 创建只扫描指定块 ID 的 `GhosttyBlockSearchController`；`App` 暂存该目标并聚焦同一个 `SearchInline`，placeholder 仍为「在命令块中查找」。
- 目标差异只在控制器：全文搜索走 `GhosttySearchController`，局部搜索走 `GhosttyBlocks.searchBlock`；输入框、正则开关、前后匹配、Escape 和关闭按钮均复用。
- 关闭弹窗、点击弹窗外、切换活动叶节点或清空块元数据时清除局部目标和高亮；随后 Ctrl+F 回到活动终端的全文搜索。

### Ctrl+L 清屏（仅 Windows）

- 拦截点：`src/modules/terminal/ghostty/useGhosttyTerminalSession.ts` 的 `createGhosttyInput`，经 `GhosttyInputController` 的 `onKeyDown` 钩子。
- 条件：Windows 且 Ctrl+L 且块会话处于 `prompt` 模式；其余情况（运行中命令、alt 屏、其他平台）按键照常直通 PTY。
- 行为：调用 `clearGhosttySession(leafId)`（清块元数据 + `model.clear()` 清缓冲），随后在 `prompt` 模式下把 `^L`（0x0C）转发给 Shell。
- 原因：单靠宿主清屏会让 ConPTY 与前端模型发散——ConPTY 维护自己的屏幕缓冲，之后仍按旧绝对坐标绘制下一条命令，命令落在屏幕中部且无提示符文本；转发 `^L` 让 PSReadLine 的 Clear-Host 清空 ConPTY 缓冲并发出双方一致的全屏重绘。直接直通而不先清模型则会因模型侧残留滚动缓冲导致重绘内容被拆散到大片空白行中（实测抓包复现：`ESC[2J`+`ESC[H`+23 行 `EL+CRLF` 后跟 `ESC[8;9H` 等重绘序列）。

```text
右键终端
  -> 读取 session.getSelection()
  -> 有非空选区：阻止块 ContextMenu，保留选区 Ask AI 流程
  -> 无选区：clientY -> viewport row -> buffer line
  -> GhosttyBlocks.blockAtLine
  -> BlockContextMenu
  -> rerun / clipboard / AI prefill / block search
```

### Ctrl+R 历史搜索

- 保留判定：`src/modules/shortcuts/shortcuts.ts` 的 `isTerminalHistoryBinding`。
- 全局释放：`src/modules/shortcuts/lib/useGlobalShortcuts.ts` 不匹配该绑定，包括旧用户偏好中的绑定，按键随后到达 Shell，由 PSReadLine 或 readline 完成反向历史搜索。
- 设置警告：`src/settings/sections/ShortcutsSection.tsx` 拒绝保存并在当前快捷键行显示中英文冲突警告。

## 4. 数据流与关键流程

1. Shell 集成发出 OSC 133 A/B/C/D，Ghostty parser 创建 tracked pins，块控制器维护有界历史。
2. `TERAX_BLOCKS=1` 时 Shell 在每个提示符上方输出一至两行空行作为块头间隔；提示符文本本身照常渲染。
3. 每个终端叶节点都挂载 `GhosttyBlockOverlay`，普通、隐私和代理终端不再有行为分支。
4. 用户直接在原生提示符处输入命令；命令文本来自终端回显，块数据来自 Shell 上报的 OSC 133 C cmdline（zsh、fish、PowerShell）或 Terax 提交记录（重跑）。
5. 右键先检查非空选区。有选区时块菜单不打开；无选区时才进行块命中。
6. 命中命令、输出或块头后，`BlockContextMenu` 读取同一个块控制器，不维护第二份输出副本。
7. 「在命令块中查找」创建指定块 ID 的局部控制器并聚焦共享 `SearchInline`；扫描沿用有预算、可取消的块搜索，正则开关在块内同样生效。
8. Ctrl+R 在 window 捕获阶段被全局快捷键分发跳过，随后进入 Shell 自身的历史搜索。
9. 设置页录制到 Ctrl+R 时不写 preferences，避免仅靠默认值造成保护漏洞；旧偏好里已有的冲突绑定也显示警告，清除或重置后警告消失。

## 5. 对外接口

- `GhosttyBlocks.blockAtLine(line, cellHeight): PositionedBlock | null`：供右键命中使用。
- `BlockContextMenu`：接收块、输出读取、重跑、搜索和焦点恢复回调。
- `GhosttyBlockOverlay`：接收 `leafId`、`onCloseSearch`，不再渲染独立搜索框。
- `GhosttyBlockSearchController`：实现 `TerminalSearchController`，将共享弹窗的查找/导航调用限定到构造时指定的块 ID。
- `isTerminalHistoryBinding(binding)`：识别精确的 Ctrl+R，不含 Shift、Alt 或 Meta。
- 无新增 Tauri command、HTTP 接口或持久化格式。

## 6. 配置与依赖

- Shell 集成：OSC 7 与 OSC 133 A/B/C/D；命令边界不能从可见文本猜测。
- 输入模式：`prompt`、`running`、`alt`、`plain`。`plain` 表示 Shell 缺少命令边界上报（如 bash 4.4 之前）或尚未集成，此时没有块装饰，输入与其他模式一致。
- 环境变量：`TERAX_BLOCKS=1` 表示预留块头间隔空行；取值为空时不预留。
- 用户偏好：`shortcuts` 仍可含历史遗留 Ctrl+R，但全局分发层必须忽略它。
- AI 附加：复用 AI 面板 prefill，输出继续经 `capAttachOutput` 截断。

## 7. 已知限制与注意事项

- 没有 OSC 133 C 边界的输出无法可靠划分命令与结果块，不应通过文本启发式伪造边界。
- bash 4.4 之前没有 PS0 预执行钩子，上报 `terax_blocks=0`，因此没有块装饰，也不能重跑或复制命令。
- 重跑需要完整命令来源：Terax 提交（重跑链路）或 Shell 上报的未截断命令行；集成脚本在 256 字符处截断，达到上限的命令不会重跑。
- 右键空白处或未命中块时不打开块菜单。
- Windows PowerShell 5.1 下 ConPTY 会把 Shell 集成发出的 `OSC 133;C;<命令>` 改写为无载荷的 `133;B`（实测抓包确认），导致端到端收不到 `end-of-input`、完全没有块；pwsh 7 不受影响。要让 5.1 也有块需要绕过 ConPTY 的命令通道（如 Rust 侧解析 VS Code 风格的 `OSC 633;E`），尚未实现。
- Ctrl+L 宿主清屏仅在块会话为 `prompt` 模式时生效；若 ConPTY 流丢失 OSC 133 D 使模式卡在 `running`，Ctrl+L 仍会直通 Shell（此时重跑菜单不受影响）。
