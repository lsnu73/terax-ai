## 1. 业务需求

预览页的端口按钮需要展示常用开发服务器端口，例如 Vite 和 Next.js。用户还应能新增自己的端口、修改已有端口的名称、端口号和说明。空态提示中的「端口」文字也要能打开与左上角端口按钮相同的菜单。端口配置在应用重启后保留。

调用链：

```text
端口按钮 / 空态"端口"
  -> PreviewAddressBar.openPorts
  -> PortPreset 菜单项
  -> tryPort 探测 localhost
  -> onSubmit 更新预览 URL
```

新增或编辑链路：

```text
菜单项 -> PortPresetDialog -> 校验
  -> setPreviewPortPresets -> terax-settings.json
  -> prefs-changed 事件 -> usePreferencesStore
```

## 4. 数据流与关键流程

1. `DEFAULT_PREVIEW_PORT_PRESETS` 提供首次启动的 Vite、Next.js 等端口，每条有稳定 `id`。
2. 偏好加载时，`normalizePreviewPortPresets` 校验已保存数据，保留用户编辑，并按 ID 和端口去重。
3. 已保存数据缺少的新内置预设会追加到列表尾部，已有同 ID 的编辑版本不会被覆盖。
4. 菜单项点击后，`tryPort` 探测 `http://localhost:<port>`，可达时更新地址栏并打开预览。
5. 编辑按钮或「添加端口」打开 `PortPresetDialog`。
6. 表单校验名称非空、端口在 1 到 65535、端口不与其他条目重复。
7. 保存使用 `upsertPreviewPortPreset` 按稳定 ID 替换或追加，再写入偏好 store。
8. 跨窗口偏好事件刷新所有预览地址栏，端口菜单在应用重启后保持用户配置。

## 5. 对外接口

- 用户接口：预览地址栏端口菜单、空态「端口」按钮。
- 前端组件契约：`PreviewAddressBarHandle.openPorts()`。
- 持久化键：偏好文件 terax-settings.json 中的 `previewPortPresets`。
- 数据契约：`PreviewPortPreset` 位于 `src/modules/preview/lib/portPresets.ts`。
- HTTP 接口：无新增，端口探测是运行时 `fetch`。

## 6. 配置与依赖

- 默认端口：定义在 `src/modules/preview/lib/portPresets.ts`。
- 用户配置：全局偏好，不按 Space 或标签页隔离。
- 预览 URL：仍由每个预览标签自身的 URL 和 Space 持久化负责。
- 无环境变量和第三方服务依赖。

## 7. 已知限制与注意事项

- 当前没有删除端口和调整顺序的界面。
- 端口探测只针对 `localhost`，不探测局域网主机或自定义协议。
- 保存的是完整端口列表，不是自定义项差集；新增默认项依靠稳定 ID 合并。
- `src/modules/settings/store.ts` 只引用预览模块的纯数据文件，不能让纯数据文件反向依赖 settings store，否则形成模块环。
- 既有内置端口可以被用户修改，后续修改默认值时已有用户仍保留自己的版本。
