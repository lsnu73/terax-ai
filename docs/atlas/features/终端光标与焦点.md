# 终端光标与焦点

- 最后校验：2026-11-12
- 状态：已覆盖
- 设计原因：[终端光标使用三层焦点](../../lore/decisions/2026-11-12-终端光标使用三层焦点.md)

## 1. 业务需求

终端只有在原生窗口聚焦、所在标签可见且为活动窗格、终端 textarea 实际持有键盘焦点时，才显示用户配置的光标样式。开启光标闪烁时，也只有满足这些条件才运行闪烁定时器；焦点进入 AI Composer、搜索框或其他控件后，光标必须隐藏。AI 面板打开时自动聚焦提示词输入框，关闭后聚焦当前活动终端。最近路径弹窗选择路径或关闭后也恢复终端键盘焦点，即使 AI 面板仍打开。

## 2. 入口与调用链

- 真实输入焦点：`src/modules/terminal/ghostty/input/GhosttyInputController.ts:401` 的 focus/blur 处理通过 `onFocusChange` 上报。
- 会话接线：`src/modules/terminal/ghostty/useGhosttyTerminalSession.ts:911` 的 `createGhosttyInput` 把回调接到当前 surface；`src/modules/terminal/ghostty/useGhosttyTerminalSession.ts:218` 同步可见性和逻辑活动窗格。
- 原生窗口焦点：两个 runtime 复用 `bindTerminalWindowFocus`，把 DOM/Tauri 焦点事件扇出到 surface 的 `handleWindowFocus`。
- WebGPU：`src/modules/terminal/ghostty/gpu/WebGpuTerminalSurface.ts:1462` 计算 `showCursor`，不满足焦点条件时向 ScreenUniform 写入空光标矩形。
- WebGL：`src/modules/terminal/ghostty/webgl/WebGlTerminalSurface.ts:499` 向 renderer 传递受焦点门控的 `cursorVisible`。
- AI 打开：`src/modules/ai/lib/composer.tsx:87` 在 Composer 挂载和 `focusSignal` 变化时聚焦 textarea。
- AI 关闭：`src/app/App.tsx:495` 检测 `aiPanelVisible` 从 true 变为 false，通过 `TerminalPaneHandle.focus()` 恢复当前活动终端。
- 最近路径关闭：`src/app/App.tsx:482` 的 `focusActiveTerminalLeaf` 是统一恢复入口；`:487` 检测弹窗 true -> false，下一帧聚焦当前活动终端；`src/modules/terminal/path-history/PathHistoryDialog.tsx:98` 阻止 Radix 关闭焦点还原。

```text
终端 textarea focus/blur
  -> GhosttyInputController.onFocusChange
  -> surface.setInputFocused
  -> 启停 blink timer + 调度重绘
  -> WebGPU 空/实光标矩形 或 WebGL cursorVisible

AI 面板打开 -> AiComposerProvider 挂载 -> Composer textarea.focus
AI 面板关闭 -> App true -> false 边界 -> 当前 activeLeafId -> TerminalPaneHandle.focus
最近路径弹窗关闭 -> App true -> false 边界 -> 当前 activeLeafId -> TerminalPaneHandle.focus
```

## 4. 焦点语义与关键流程

| 状态 | 来源 | 职责 |
|---|---|---|
| `windowFocused` | DOM/Tauri 原生窗口事件 | 切出应用时隐藏光标并停止闪烁 |
| `focused` | 标签的 `activeLeafId` | 标识逻辑活动窗格，同时继续服务 frame pacing |
| `inputFocused` | 终端 textarea 的 DOM focus/blur | 判断终端是否实际持有键盘焦点 |

1. 三种焦点缺一不可；原生窗口聚焦不代表焦点仍在终端，AI Composer 获得焦点时窗口仍然聚焦。
2. 焦点恢复时先把光标相位重置为可见，再按用户设置继续闪烁；关闭闪烁时显示稳定光标。
3. 窗口 focus/blur 和输入 focus/blur 都调度重绘，因此非闪烁光标也不会在 blur 后残留。
4. Ghostty 的原生光标可见性、样式和用户设置不改写；焦点只影响 presentation。
5. AI 关闭恢复到关闭当下的活动终端窗格；非终端标签或已销毁句柄安全跳过。
6. 最近路径弹窗无论选择路径还是直接关闭都恢复当前活动终端；AI 面板仍打开时不由 Radix 把焦点还原到 Composer。

## 5. 对外接口

- `GhosttyInputControllerOptions.onFocusChange?: (focused: boolean) => void`。
- 两种 surface 的 `setInputFocused(focused: boolean)`，由会话输入控制器调用。
- `shouldCursorBlink(blinkEnabled, windowActive, slotFocused, inputFocused)` 纯函数。
- 终端恢复复用 `TerminalPaneHandle.focus()`，不新增全局焦点 store。

## 6. 验证与已知限制

- 2026-11-12：`src/modules/terminal/lib/cursorBlink.test.ts`、`src/modules/terminal/ghostty/input/GhosttyInputController.test.ts` 与 WebGPU/WebGL surface 测试共 86 项通过；`pnpm check-types` 通过。
- 测试覆盖真实输入焦点回调、窗口/窗格/输入焦点组合、非闪烁光标重绘及定时器启停。
- AI 面板真实 DOM 开关焦点链暂无 jsdom/Testing Library 自动化覆盖，需要桌面手测快捷键、拖拽、prefill 和快速开关。
- 关闭 AI 后恢复当前活动终端，不记录并强制切回打开 AI 之前的标签；期间切换到非终端标签时不聚焦隐藏终端。
