- 最后校验：2026-11-06

## 业务需求

设置窗口的「关于」分区：展示应用名称、标语、版本、构建平台、包标识与许可证，提供指向 GitHub 仓库的源代码链接，以及「检查更新」「在 GitHub 查看」「报告问题」三个操作按钮。检查更新按钮由更新模块驱动，显示检查中/下载中/已是最新等状态与下载进度。

关于页同时列出软件在本机留下的全部痕迹：安装目录与可执行文件、应用数据/配置/本地数据/缓存/日志目录、偏好与 AI 配置文件、AI 会话目录、WebView 数据目录、开始菜单与桌面快捷方式、注册表项（开机自启与卸载信息）以及凭据存储。每条痕迹都有复制按钮，不存在的条目标注「未找到」，并可手动刷新。

## 入口与调用链

- 设置窗口分区导航 → `src/settings/SettingsView.tsx` 渲染各分区 → `src/settings/sections/AboutSection.tsx:24` `AboutSection` 组件。
- 版本/名称来自 `@tauri-apps/api/app`（`getVersion`/`getName`），平台与架构来自 `@tauri-apps/plugin-os`（`platform`/`arch`）。关于页面版本由构建时的 `src-tauri/tauri.conf.json` 决定，Git tag 不会直接修改它。
- `pnpm release:version <x.y.z>` 调用 `scripts/release-version.mjs`，同步 `package.json`、Tauri 配置、Cargo workspace 与三个本地 lockfile 包；`--check v<x.y.z>` 只读校验七个版本位置和 tag。
- 检查更新按钮调用 `src/modules/updater` 的 `useUpdater`（`src/modules/updater/useUpdater.ts:85`）。Windows 和 macOS 通过 Tauri updater 读取 `src-tauri/tauri.conf.json` 配置的 `latest.json`，Linux 通过 `GITHUB_LATEST_RELEASE` 读取本仓库 Releases 最新版 API。
- 推送 `v*` 标签触发 `.github/workflows/release.yml`，先用发布脚本拒绝版本漂移和 tag 不匹配，再在 Windows Runner 构建 NSIS 安装包并发布 Release，上传安装包、minisign 签名与 `latest.json`。
- 安装包发布完成后，工作流调用 GitHub Releases generate-notes API，按 `.github/release.yml` 的 PR 标签分类生成变更记录，并将固定安装说明与变更记录写回当前 Release。
- 痕迹清单：`AboutSection` 挂载时 `invoke("app_traces")`（`src/settings/sections/AboutSection.tsx:85` 的 `loadTraces`），按 `kind` 分组渲染；Rust 端 `src-tauri/src/modules/traces.rs:151` 的 `app_traces` 解析各路径后在 blocking 池做存在性检查（`:165` 的 `collect`），Windows 额外读取注册表与快捷方式（`:73`）。

## 对外接口

- Windows 和 macOS 的更新检查读取 `https://github.com/lsnu73/terax-ai/releases/latest/download/latest.json`，Linux 走 GitHub Releases API。Tauri updater 签名公钥见 `src-tauri/tauri.conf.json`，发布私钥只进入 GitHub Actions Secrets。
- IPC：`app_traces()` 返回 `{ id, kind, value, exists }[]`，`kind` 为 `install | config | data | cache | logs | registry | credentials`。命令只读，不接受参数，不修改任何文件或注册表。
- 痕迹条目的显示名由前端按 `id` 查 `settings.about.traces.items.*` 文案，缺少词条时回退显示 `id`。

## 已知限制

- 包标识为 `app.wang.terax`；修改包标识会影响应用配置目录与更新标识。
- 自动发布工作流当前仅覆盖 Windows NSIS，未配置 Apple 签名、公证或 SignPath；macOS 和 Linux 安装包仍需单独构建发布。
- Linux 客户端只提示新版本并打开 Release 页面，不自动下载安装。
- 首个包含新公钥和更新端点的版本需要手动安装，之后才能通过本仓库的 Release 自动更新。
- 发布脚本只接受稳定版本 `x.y.z`，不自动 push；`--tag` 必须与 `--commit` 一起使用，并要求工作区干净。
- 痕迹清单里的注册表项与快捷方式只在 Windows 出现；macOS 显示 Keychain 服务名，Linux 显示 `secrets.json` 路径。
- 自动启动与卸载注册表项按路径与名称启发式判断是否存在（自启动项要求值名或值内容包含 terax），不做完整安装器状态核对。
- 凭据条目只展示存储位置与服务名 `terax-ai`，不读取或展示任何密钥内容。
