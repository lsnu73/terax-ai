# 设置页左侧导航与搜索结果分组

- 日期：2026-11-04
- 状态：已采纳
- 关联约束：无
- 关联坑点：无

## 背景

设置页原先在顶部横向排列八个分区标签，搜索栏单独占一行。分区增加后，顶部导航与搜索栏持续挤占垂直空间；英文分区名较长时，横向标签的可用宽度不足。搜索结果是一份扁平列表，每条结果只带一个分区标签，用户需要逐条辨认分类，难以看出同一分类下的设置分布。

搜索跨度覆盖全部分区，但搜索框跟随左侧导航栏时只有约 13rem 宽。若结果浮层沿用导航栏宽度，较长的设置说明会被单行截断，用户无法在结果列表中读完整内容。

## 候选方案

### 页面布局

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：左侧固定栏、搜索框第一、竖向分区导航 | 搜索优先，分区名有完整水平空间，内容区获得更多垂直空间 | 左侧栏永久占用约 13rem 宽度 |
| B：保留顶部横向导航，搜索框置于顶部 | 改动最小，内容区更宽 | 分区与搜索继续挤占垂直空间，窄窗口下标签易压缩 |

### 搜索结果的分类表达

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：按分区归组，分类单独一行作为组标题 | 分类层级清楚，同一分类的结果集中，减少重复标签 | 结果列表比扁平列表更高 |
| B：扁平列表，每条结果显示位于右侧的分类标签 | 列表紧凑 | 分类与结果关联弱，长结果下分类容易被忽略 |
| C：扁平列表，每条结果纵向显示分类 | 比 B 清楚 | 分类重复出现，仍无法形成分类层级 |

### 搜索浮层宽度

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：脱离导航栏宽度，按内容扩展，上限 40rem 或视口 | 设置说明可完整阅读，不因搜索框窄而截断 | 浮层会覆盖右侧内容区 |
| B：固定为左侧导航栏宽度 | 视觉与搜索框对齐 | 长说明被截断，无法展示完整搜索结果 |
| C：固定宽度的独立浮层 | 宽度可预测 | 短结果浪费空间，窄窗口仍需额外适配 |

## 结论与理由

采用左侧固定栏、搜索框第一、竖向分区导航，并让搜索结果按分区独立分组。分类标题使用独立标题栏、主色竖条和结果数量，组内结果通过左侧引导线形成视觉归属，用户无需逐条阅读分类标签即可理解结构。

搜索浮层的最小宽度与搜索框一致，按内容扩展到 40rem 或视口上限，标题和说明完整换行。搜索属于跨分区能力，不应被承载它的导航栏宽度限制。

以下条件应重新评估：

- 设置分区数量继续增加，左侧导航需要滚动或折叠。
- 出现小屏或移动端布局，13rem 固定栏与最大 40rem 浮层都不再适合。
- 搜索结果需要支持分类折叠、分类筛选或常驻搜索面板。
- 浮层覆盖内容区导致定位目标被遮挡，且用户反馈无法接受时。
