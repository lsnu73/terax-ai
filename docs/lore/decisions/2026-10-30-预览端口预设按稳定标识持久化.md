# 预览端口预设按稳定标识持久化整张列表

- 日期：2026-10-30
- 状态：已采纳

## 背景

预览端口菜单原本把 Vite、Next.js 等预置项写在组件内，既不能新增也不能修改。需求要求用户新增端口、编辑已有端口，并在应用重启后保留配置。内置项也必须可编辑，因此不能把内置项视为不可变常量。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）完整列表存入偏好，每条有稳定 `id`，加载时合并缺失的内置项 | 内置项和自定义项走同一编辑路径；保留用户修改；跨窗口同步简单 | 偏好文件保存整表；默认值变更需要谨慎设计 |
| B 只存自定义项，内置项只读 | 默认值随版本自动更新 | 无法满足「修改现有端口」的需求 |
| C 只存端口数字数组 | 数据最小 | 丢失名称、说明和稳定编辑目标 |

## 结论与理由

采用 A。`PreviewPortPreset` 包含 `id`、`port`、`label`、`hint`。编辑时保持原 ID，因此内置项被修改后不会被默认值覆盖。`normalizePreviewPortPresets` 负责恢复合法条目、按 ID 和端口去重，并把当前版本新增且缺失的默认项追加到末尾。用户配置保存在 `terax-settings.json` 的 `previewPortPresets`。

模块依赖必须保持单向：`settings/store.ts` 可以引用预览模块的纯数据 `lib/portPresets.ts`，但 `portPresets.ts` 不得引用 settings store，否则形成模块环。

**重新评估条件**：如果需求变成按 Space 或按项目隔离端口列表，或者支持删除和排序并需要区分「被删除的内置项」，届时需要增加墓碑标记或把配置迁移到项目级存储。
