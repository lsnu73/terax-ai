# 终端统一采用命令与结果块

- 日期：2026-10-30
- 状态：已接受（同日修正：块改为叠加装饰，不接管输入）
- 相关功能：[终端命令与结果块](../../atlas/features/终端命令与结果块.md)
- 相关约束：[INV-013](../invariants.md#inv-013)、[INV-014](../invariants.md#inv-014)、[INV-016](../invariants.md#inv-016)

## 背景

此前「命令块」是独立标签类型，普通终端只承担传统网格交互。两套入口让新建菜单、命令面板、快捷键、分屏、工作区恢复和输入栏都依赖 `blocks` 标志。用户需要的是同一种终端体验：每条命令及结果都是可操作的块，而不是先选择一种特殊终端。

第一版实现把所有终端都切到了原命令块页面的输入方式：隐藏原生提示符、用底部共享命令输入区代替直接输入。用户反馈这等于「删掉了终端、留下了命令块页面」：他们要保留的是能看到 PowerShell 原生提示符并在其中直接输入的终端。同日修正为：提示符与输入保持原生，块只作为叠加装饰。

同时，终端已经有文本选区右键的「问问 Terax」流程。新增块菜单不能覆盖选区语义，也不能让两个菜单同时出现。Ctrl+R 还需要从可配置全局快捷键中释放，交给终端历史搜索。

## 决策

1. 删除独立命令块标签类型、创建入口、命令面板项和专属快捷键，不为旧标签保留第二套运行时分支。
2. 所有 PTY 统一启用既有 OSC 133 块管线，所有终端叶节点统一挂载块覆盖层。
3. 终端始终保持原生 Shell 提示符与直接输入。`TERAX_BLOCKS=1` 只让 Shell 在每个提示符上方输出块头间隔空行；提示符文本照常渲染，按键、组合文本与粘贴始终直通 PTY。
4. 命令与结果边界继续来自 OSC 133 A/B/C/D 和 Ghostty tracked pins。右键命中只把坐标换算到 native buffer line，再查询块控制器，不解析可见文本猜测边界。
5. 块操作以 `BlockContextMenu` 右键菜单提供。块查找与 Ctrl+F 共用 `SearchInline`，右键入口只提供限定块 ID 的搜索控制器，不再维护独立 SearchBar。
6. 非空文本选区优先于块菜单。无选区且命中命令、输出或块头时才打开块菜单。
7. 新建隐私终端默认改为 Ctrl/Cmd+Shift+T。Ctrl+R 是终端保留键，全局快捷键分发和设置保存两层都要防护；按键本身交给 Shell 的反向历史搜索（PSReadLine 或 readline）。
8. 重跑能力信任两类完整命令来源：Terax 提交记录（重跑链路）和 Shell 上报的未截断 OSC 133 C cmdline；集成脚本在 256 字符处截断，达到上限的命令不重跑。

## 为什么复用既有块管线

普通终端和原命令块已经共享同一个持久 Ghostty model。OSC 133 tracked pins 能在 reflow、scrollback 和 renderer 替换后维持命令边界，并有有界历史、输出读取、搜索和重跑能力。另建右键输出副本或文本解析模型会引入边界错误、内存双份和状态失效问题。

统一启用块会话后，`blocks` 不再是标签的业务属性。旧工作区 JSON 中多余的 `blocks` 字段可以在反序列化时自然忽略，不需要迁移文件或保留兼容分支。

## 为什么块不能接管输入

终端的定义是原生 Shell 交互：用户在 PowerShell 提示符处输入、用 Shell 自己的补全和历史搜索。隐藏提示符并替换为共享输入区会删掉这层体验，也让 Ctrl+R 必须重造一个 CodeMirror 历史弹层去模仿 Shell 行为。保持原生输入后，块装饰与块操作的实现完全不需要改动输入路径，只需 Shell 集成继续上报 OSC 133 并预留块头空行。

块几何依赖的间隔空行由 precmd（zsh、bash）或 prompt 函数（PowerShell、fish）直接输出，而不是拼接进 PS1，避免每次重绘时在用户提示符前累积前缀。提示符标记通过受保护的注入保持幂等，框架重建提示符（p10k、starship）时能自动补回 OSC 133 B。

## 交互约束的原因

文本选区表示用户要操作一段任意文本，块命中表示用户要操作一条命令及其结果。两者语义不同，不能仅凭右键坐标决定。选区优先确保「问问 Terax」仍针对用户选中的原文；只有没有选区时，才把右键解释为块操作。

Ctrl+R 的保护不能只修改默认绑定。旧偏好或手工配置仍可能让 window 捕获阶段的全局处理器先截获按键，因此分发层必须始终排除它。设置页还要拒绝新绑定并给出警告，避免用户保存一个看似成功但实际不生效的配置。

## 影响与后续维护

- 新增终端创建路径不得重新引入块化开关；所有终端都应获得相同的块能力。
- `plain` 表示 Shell 缺少命令边界上报（bash 4.4 之前）或尚未集成，此时没有块装饰，但输入与其他模式一致。
- 修改右键或选区逻辑时，必须同时检查两种菜单的互斥关系。
- 修改全局快捷键匹配、偏好迁移或设置录制时，必须保留 Ctrl+R 防护。
- 重新评估本决策的前提：终端模型不再提供可靠 OSC 133 边界，或产品重新需要完全无块的原生终端模式。届时应先设计显式用户级模式，而不是恢复隐蔽的标签类型分支。

> 修订于 2026-11-02：块搜索不再复用块覆盖层的原 SearchBar，改为与 Ctrl+F 共享 SearchInline；根因见 [命令块查找焦点被终端抢回](../pitfalls/2026-11-02-命令块查找焦点被终端抢回.md)。
