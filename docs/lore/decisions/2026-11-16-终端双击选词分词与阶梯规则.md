# 终端双击选词采用规则分词与双阶梯递进

- 日期：2026-11-16
- 状态：已采纳
- 关联坑点：[pitfalls/2026-11-16-宽字符spacer与空白填充同为空串.md](../pitfalls/2026-11-16-宽字符spacer与空白填充同为空串.md)

## 背景

旧实现只有三类字符（space/word/punctuation）加同类扩展：CJK 宽字符第二列 spacer 归入 punctuation，双击中文只能选中半个字；`/usr/local/bin`、`v1.2.3`、`foo_bar` 等全部碎成片段。重写时拿到一份需求文档（双击分词功能.md），其规则表与示例存在自相矛盾（冒号既是 UrlGlue 又被示例断开；四击既说逐行扩展又在第五击跳全选），由用户逐项裁定后形成最终行为规范。硬约束是 TERAX 的性能底线：无词典、零依赖、点击时才做 O(cols) 扫描。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 纯规则分类 + token 化 + 容器/路径双阶梯（最终采用） | 零依赖零缓存；CJK 连块、路径/引号递进一条状态机全覆盖；行为可测试锁定 | 规则多（冒号、点号、段字符集各有特例），需要测试矩阵维护 |
| jieba 类词典分词 | 中文分词更"智能" | 中文不需要分词（连续 CJK 块即可），词典内存与加载时间违背轻量约束 |
| 需求文档原案：PathSep/UrlGlue 永不切断 | URL、路径双击即整条 | `key:value`、`error:` 连冒号一起选中；路径段（`atlas`）无法单独复制 |
| 旧三类同类扩展（保持现状） | 实现最简 | 中文半个字、路径碎片，用户不可接受 |

## 结论与理由

1. **不可分割单元优先于分隔**：冒号在时间（`18:30`）、IPv6/MAC（两侧十六进制位）、`host:port` 内粘连；后跟斜杠时是路径分隔符（盘符 `C:\`、`https://`）；其余（`error:`、`key:value`）断开。点号只在数字两侧粘连（`v1.2.3`、`127.0.0.1`），字母间的点断开交给路径阶梯。
2. **斜杠/反斜杠一律断词**，路径整体通过路径阶梯到达：词 → 路径段（`changelog` → `changelog.md`）→ 整条路径（`docs/atlas/changelog.md`）；段已等于词时（`atlas`）直接跳整条路径。这是用户明确裁定的行为，覆盖了需求文档"PathSep 不切断"的原案。
3. **双阶梯并列、容器优先**：三击起先试引号/括号容器阶梯（内部 → 含定界符 → 外层），未命中再走路径阶梯，都未命中回落整行并封顶。四击块扩展与五击全选被用户否决（维持三击封顶）。
4. 实现集中在 `selection/wordSelection.ts` 纯函数，模型与控制器只做委托，保证无 WASM、无 IPC、无缓存。

未来重新评估的条件：用户要求 URL 双击直接选整条（可给 scheme 路径单独的整段直选规则）；需要配置化分词符（引入用户可编辑的分隔符集合）；Ghostty 原生提供词边界 API（可替换规则扫描）。
