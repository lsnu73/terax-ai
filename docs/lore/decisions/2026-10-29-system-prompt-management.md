# 系统提示词管理：三级继承 + 文本覆盖 + 自定义强制拼接工具协议尾段

- 日期：2026-10-29
- 状态：已采纳
- 关联约束：INV-003（terax-ai-models.json 唯一事实来源）、INV-006（同一 normalize 校验链路）、INV-008（每个配置项带 info 说明）

## 背景

系统提示词原本只有模型级 `systemPrompt: "full" | "lite"` 二选一，且内置文本不可查看、不可修改。用户需要：（1）查看/编辑内置 full 与 lite 提示词并可恢复默认；（2）完全自定义提示词；（3）在全局、Provider、模型三个层级分别选择用哪一套。同时担心与「设置 → AI 行为」页（时名「代理」）的自定义指令功能冲突。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）全部存进 `terax-ai-models.json`：`prompts` 覆盖文本 + 三级 `systemPrompt` 档位 | 单一事实来源不变；手改 JSON 与 UI 编辑天然等价；normalize 单链路校验直接复用 | 配置文件变大（提示词全文入库） |
| B 提示词文本单独存一个文件，档位留在 models.json | 配置文件保持小巧 | 引入第二个事实来源与第二条读写链路，违背 INV-003 精神 |
| C 自定义提示词追加在内置提示词之后 | 用户写坏也不会丢工具协议 | 与「自定义」语义相悖，且无法精简 token |

自定义提示词与工具协议的取舍：

| 方案 | 优点 | 缺点 |
|---|---|---|
| D（最终采用）替换内置 + 强制拼接 `TOOL_PROTOCOL_TAIL` | 用户文本生效干净，工具清单与审批规则不丢 | 尾段不可关（有意的安全约束） |
| E 完全替换，不加任何尾段 | 最自由 | 用户不知道工具清单格式，agent 立即丧失工具能力，且难以排查 |

与 AI 行为页的关系：该页（时名「代理」，本功能后续迁入此页）的自定义指令/人格/片段是 `agent.ts` 的 `buildStableSystem` 里的**追加层**，本功能管理的是**基础层**，技术上不冲突；但概念相近（都「自定义提示词」），故两处各加互指文案说明边界，而不是合并功能。2026-10-29 后续调整：该模块已从「模型」页迁入「AI 行为」页顶部，与追加层同页展示。

## 结论与理由

选 A + D + 互指文案。

- 档位解析链：`model.systemPrompt ?? provider.systemPrompt ?? defaults.systemPrompt ?? "full"`（`registry.systemPromptKind`）。字段全部可选，缺省即「跟随上级」，避免在三层各写死默认值。
- 文本覆盖：`AiConfig.prompts = { full?, lite?, custom? }` 只存实际修改过的档；空字符串在 normalize 阶段丢弃（等于未覆盖）。
- `custom` 档运行时拼接 `TOOL_PROTOCOL_TAIL`；`custom` 文本为空时回退内置 `full`，不产生「空系统提示词」这种故障态。
- 新模型不再写死 `systemPrompt: "full"`，默认跟随上级，全局改档即全量生效。

**重新评估条件**：若用户要求按会话/按 agent 人格选择基础提示词（目前是模型维度），或要求关闭工具协议尾段（如纯聊天场景），届时再引入第四层级或尾段开关。
