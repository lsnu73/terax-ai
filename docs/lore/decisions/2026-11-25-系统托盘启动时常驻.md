# Windows/macOS 系统托盘在启动时常驻

- 日期：2026-11-25
- 状态：已采纳
- 关联约束：INV-025
- 关联坑点：无

## 背景

原实现只在用户选择「缩小到托盘」时才创建托盘图标，主窗口可见时通知区域没有 Terax 入口。用户明确需要不先关闭主窗口，也能直接从托盘退出程序；按需创建让这个操作多了一步，也使用户误以为程序没有托盘能力。

同时，托盘右键菜单的「打开 Terax」与「关闭程序」使用 Rust 侧文案。创建时机若早于 i18n 初始化，菜单会使用尚未确定语言的标签。Linux 构建没有托盘后端，不能为了跨平台一致引入隐藏窗口后无法恢复的入口。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：Windows/macOS 启动时创建并常驻托盘 | 主窗口可见时即可恢复或退出；关闭窗口只隐藏，不改变托盘生命周期；原生退出不依赖前端存活 | 从启动起持续占用通知区域或菜单栏空间；创建失败需要不阻断启动的降级策略 |
| B：保持按需创建 | 用户不驻留时通知区域没有图标 | 无法满足「不关窗口直接从托盘退出」；每次关闭到托盘都要重新确认原生入口 |
| C：启动时创建，隐藏窗口时再销毁 | 首次满足直接托盘退出 | 窗口隐藏后入口消失；窗口隐藏失败还可能留下用户看不见的托盘，生命周期更复杂 |

## 结论与理由

采用 A。托盘不是「窗口关闭后的替代品」，而是与主窗口并存的常驻控制入口，因此其生命周期必须覆盖整个进程，不能跟随窗口显隐变化。关闭窗口仍然只负责隐藏；恢复窗口和直接退出都复用同一个原生托盘。

创建动作放在 i18n 初始化之后、React 首次渲染之前：既保证菜单标签使用当前语言，也不让托盘创建失败阻断页面启动。Windows/macOS 启动时创建失败只记录日志，之后选择「缩小到托盘」仍可重试；Linux 不创建托盘，隐藏失败时回落为正常退出，避免窗口消失后无法找回。

托盘保留到进程结束，不提供前端销毁命令。重新引入 `tray_hide` 或把托盘生命周期绑定到窗口显隐，会直接破坏常驻入口契约。托盘「关闭程序」仍沿用 Rust `app.exit(0)` 的直接退出取舍，见 [2026-11-07-托盘退出直接结束进程.md](2026-11-07-托盘退出直接结束进程.md)；它不经过前端的会话落盘与脏编辑器确认。

未来重估条件：若产品要求不驻留时完全退出通知区域，应增加明确的用户偏好和原生设置联动，而不是恢复窗口关闭时销毁；若 Linux 引入稳定的托盘后端并解决隐藏后的恢复路径，再重新评估平台范围。
