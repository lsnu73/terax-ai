# 发行版启用开发者工具并分配独立快捷键

- 日期：2026-10-30
- 状态：已采纳

## 背景

主窗口无法打开 WebView 开发者控制台，但设置窗口可以。根因有两层：主窗口在捕获阶段把 `Ctrl+Shift+I` 分配给 `ai.toggleMini`，原生 WebView DevTools 快捷键到不了页面；发行版又没有启用 Tauri `devtools` feature。用户明确要求开发版和发行版都能从主界面打开控制台。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）发行版启用 `devtools` feature，新增独立 `devtools.open`，默认 Mod+Alt+I 并提供 F12 | 不改 AI 面板习惯；开发版和发行版都能用；快捷键可自定义 | 发行包包含调试能力；多占一个快捷键 |
| B 把 `Ctrl+Shift+I` 还给 DevTools，另改 AI 面板快捷键 | 符合 Chromium 用户习惯 | 破坏现有 AI 面板操作习惯，设置页和文档都要迁移 |
| C 只在 debug 构建启用 DevTools | 发行包不暴露调试能力 | 不满足用户明确提出的发行版需求 |
| D 只依赖原生菜单 | 实现简单 | Windows 与 Linux 没有对应原生菜单入口，无法覆盖三平台 |

## 结论与理由

采用 A。`devtools.open` 由快捷键注册表分发到 App，再调用 Rust `open_devtools`，对调用方 webview 执行 `open_devtools()`。`Cargo.toml` 启用 Tauri `devtools` feature，使该 API 在 release 构建中存在。`ai.toggleMini` 继续使用 Mod+Shift+I，避免两个用户动作互抢。

**重新评估条件**：如果公开发行版的政策不再允许暴露 DevTools，或 macOS App Store 限制与发行策略冲突，需要改为仅本地或签名构建启用；如果用户更希望使用 Chromium 标准的 Ctrl+Shift+I，则必须同时重新分配 AI 面板快捷键。
