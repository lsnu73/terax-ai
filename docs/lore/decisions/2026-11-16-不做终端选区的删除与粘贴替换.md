# 不做终端选区的删除与粘贴替换

- 日期：2026-11-16
- 状态：已废弃（未采纳；用户明确决定不实现）
- 关联约束：无
- 关联坑点：无

## 背景

用户希望双击选中命令行里的词（如 `git switch main` 中的 `main`）后按 Delete 或粘贴替换。当前实现只支持复制：选区是宿主侧在渲染网格上算出的显示范围（`TerminalSelectionController`），键盘输入由 `GhosttyInputController` 编码成字节直接发给 PTY，两者没有共享状态，删除与粘贴替换无从谈起。

核实结论：技术上可行（Terax 已有 OSC 133 提示符模式、光标位置、按 cells 计数、统一粘贴漏斗，可发方向键加退格宏）。用户评估后决定不实现，并要求把理由落档，避免未来重复询问。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 按键宏编辑（方向键 + 逐字符退格），提示符模式严格门控 | 能覆盖用户场景；技术上可行 | 破坏性失败模式：计数一错就删掉错误文本，shell 输入无撤销 |
| 只做「Ctrl+Shift+V 删除选区后粘贴」 | 风险面略小 | 与完整删除共用同一套宏与同一失败模式 |
| 不实现，按用户原话使用行编辑器绑定（Ctrl+W 删词、Ctrl+U 删整行、复制后手动粘贴） | 零风险、跨 shell 一致、不破坏终端分层 | 用户需要记忆按键绑定 |
| 放弃（最终选择）：记录理由，未来按重评条件再议 | 避免破坏性功能与长期维护负担 | 用户要的功能暂时没有 |

## 结论与理由

不实现。核心原因不是「做不到」，而是这个功能的失败模式是破坏性的，且依赖宿主无法可靠观测的 shell 编辑状态：

1. 终端分层：选区是宿主的复制操作，编辑缓冲在 shell 行编辑器（readline/PSReadLine/fish）里。宿主注入按键宏等于替 shell 编辑，违背「终端只是字节管道」的边界；Windows Terminal、iTerm2、VS Code、Kitty、Alacritty 均只做到复制，是同一个取舍。
2. 网格列数不等于缓冲字符数：制表符在网格里被展开成多个空格但只占 1 个字符；PSReadLine 预测建议（ghost text）占格但不在缓冲；宽字符占 2 列但只算 1 个字符；软换行处方向键语义随行编辑器不同（readline 上下键是历史、左右键才跨换行）。任一处算错，宏就删错文本。
3. 按键语义随 shell 配置变化：vi 编辑模式、自定义 `bind -x`、补全菜单（方向键在菜单内导航）都会让宏失效或产生意外结果，宿主无法可靠探测。
4. 跨主机不可移植：SSH 远端 shell 的配置与本地假设不一致时静默出错。
5. 习惯与误触：用户对终端的共识是「选区 = 复制」，让 Delete 在选区存在时变成破坏性操作存在误删风险，且收益不普遍。
6. 若未来重新实现，必须遵守当时讨论的门控：仅提示符模式、仅当前命令行的同一视觉行、选区不跨块、无法精确计数（疑似制表符展开、多行、选区不在光标行）时保持原按键行为不动；删除用逐字符退格而非 `Ctrl+W`，删除后清除宿主选区。

替代路径（已写入结论）：用行编辑器的既有绑定删词/删行，或复制后手动粘贴，零风险且跨 shell 一致。

## 未来重新评估的条件

- 终端模型或协议提供真实的输入行编辑通道（Ghostty 或 kitty/OSC 扩展暴露行缓冲、可查询光标与文本，而不是让宿主猜网格）。
- 行编辑器提供可查询、可设置的缓冲状态（例如 shell 集成协议明确告知「当前输入行文本与光标位置」）。
- 用户明确接受尽力而为与误删风险，并按上述门控重新设计交互与提示。
