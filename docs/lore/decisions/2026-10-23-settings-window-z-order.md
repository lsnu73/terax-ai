# 设置窗口取消置顶，全平台与主窗口保持同一层级
- 日期：2026-10-23
- 状态：已采纳
- 关联约束：INV-001、INV-002
- 关联坑点：无

## 背景

用户反馈：设置窗口的显示层级过高，切换到其他软件后 Terax 的设置窗口仍浮在屏幕上。原实现中 `settings_always_on_top()` 在 macOS 以外的平台返回 `true`（Windows/Linux 强制置顶），且重复打开设置窗口时还会再调一次 `set_always_on_top(true)`。需求是把设置窗口的层级调整为与主程序窗口一致。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）：全平台移除 always_on_top，仅保留「主窗口的子窗口」关系 | 行为各平台一致；代码最简单（删掉一个函数、一个 builder 标志、一处重复设置）；从结构上同时满足 INV-001 | 设置窗口不再能「钉」在屏幕上，失去浮动能力 |
| B：保留 Windows/Linux 置顶，仅修 macOS | 改动最小 | 正是被报告的 bug 行为，与需求相反 |
| C：把置顶做成用户偏好设置 | 保留灵活性 | 为一个边角需求引入新的偏好键、跨窗口同步与 UI，成本不成比例；无人提出该需求 |

## 结论与理由

选 A。设置是临时性任务窗口，「子窗口 + 普通层级」已经保证它在 Terax 之上、又随应用一起退层，符合主流桌面应用惯例。同时移除了重复打开分支里的 `set_always_on_top(true)`，并删除了只为旧行为服务的 `settings_always_on_top()` 与其测试 `settings_float_only_outside_macos`。

**未来什么条件下应重新评估**：如果有用户明确提出「希望设置窗口钉在屏幕上」的需求，应走方案 C（做成默认关闭的偏好项），而不是恢复平台级强制置顶；在 macOS 上任何恢复置顶的实现都必须先绕开 INV-001（parent 与 always_on_top 不能共存）。
