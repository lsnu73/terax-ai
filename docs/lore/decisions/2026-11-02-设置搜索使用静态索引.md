# 设置搜索使用静态索引与稳定锚点

- 日期：2026-11-02
- 状态：已采纳
- 关联约束：INV-015

## 背景

设置页需要跨分区搜索选项并定位到具体设置，但各分区不是配置驱动渲染，且只有当前分区挂载。部分分区还持有未保存草稿、展开状态和异步配置。搜索若依赖当前 DOM，就只能覆盖正在显示的分区；若为了搜索挂载全部分区，又会引入不必要的初始化与状态副作用。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A（最终采用）静态搜索元数据 + 稳定 `data-setting-id` | 只计算少量元数据；可跨分区搜索；目标 ID 不受界面语言和条件渲染顺序影响 | 新增设置项需同步索引与锚点；用户动态数据默认不逐项覆盖 |
| B 挂载全部分区后搜索 DOM 文本 | 不需要单独维护索引 | 初始化所有分区并可能扰动草稿；显示文本随语言变化，条件项与 DOM 序号不稳定 |
| C 递归遍历整个 settings 词典 | 无需登记标题键 | 按钮、错误、placeholder、插值文案会成为无法定位的噪声结果 |

## 结论与理由

采用 A。搜索是导航功能，不应以初始化所有业务分区为代价；稳定 ID 也比翻译后的文本更适合作为定位契约。快捷键直接复用现有 `SHORTCUTS` 注册表，避免为同一批稳定选项再复制一份清单。模型、Provider、Agent、片段等用户动态数据只提供区域入口，不让全局设置搜索承担数据管理器搜索职责。

新增可搜索设置项时必须同时维护索引与目标锚点，违反代价见 INV-015。条件选项通过偏好可见性规则进入结果，不通过擅自修改偏好来强制显示目标。

**重新评估条件**：若未来设置分区改为配置驱动渲染，应由同一份配置同时生成 UI 与搜索索引，消除双重登记；若需求变为搜索用户动态模型、角色或片段内容，也应评估各领域的实时索引，而不是扩大当前静态清单。
