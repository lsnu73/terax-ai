# 最近路径按视觉宽度压缩，且只作用于展示

- 日期：2026-11-24
- 状态：已采纳
- 关联约束：无
- 关联坑点：无

## 背景

最近路径弹窗需要展示 Windows、UNC、POSIX 和相对路径。路径可能包含中文、emoji 或很长的末级目录，固定字符数截断会误判宽度，普通 CSS 尾部省略又会丢掉用户要求保留的开头与末级开头。压缩只能改变视觉展示，不能改变搜索、键盘选择、无障碍名称或最终 `cd` 的路径。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 纯函数接收 `maxWidth` 与 `measureText`，派生独立展示字符串（最终采用） | 宽度规则可测试；像素、终端列等不同度量可复用；原始路径始终不变 | 调用方需提供正确测量函数，UI 要监听宽度和字体变化 |
| CSS `truncate` / `text-overflow: ellipsis` | 实现简单，浏览器自动处理溢出 | 通常只保留开头，无法保证末级开头；不能按目录视觉宽度选择隐藏对象 |
| 按字符数估算宽度 | 无需 DOM 测量 | 中文、emoji、组合字符和不同字体会严重失真 |
| 压缩后回写历史或选择值 | 数据与展示保持一致 | 破坏原始路径，可能把错误路径用于 `cd`，也会污染跨工作区历史 |

## 结论与理由

1. **宽度必须由使用场景测量。** 最近路径使用当前计算样式的 Canvas 像素宽度；纯函数不依赖 DOM，测试可注入确定性测量。这样既避免把中文字符数当成列数，也让同一规则能在未来以终端列宽复用。
2. **保留路径语义锚点。** 盘符、根目录、UNC 服务器与共享名、相对路径首段不参与隐藏；末级目录不能被完全删除。超宽时按测量宽度从最宽段开始处理，末级最宽则先截断末级，仍超宽再隐藏次宽目录，所有隐藏段合并为一个省略号。
3. **展示与数据严格分离。** `compactPath` 只返回显示文本；列表的过滤值、按钮 `aria-label`、悬浮提示和 `onPick` 继续使用原始路径。若把压缩结果用于选择，用户会进入错误目录，屏幕阅读器也会失去完整路径。
4. **布局变化必须重算。** 弹窗宽度、缩放和字体加载都会改变可用像素宽度，因此展示层在初次挂载、`ResizeObserver` 回调和字体就绪后重新测量；Canvas 不可用时回退原始路径，而不是猜测宽度。

未来重新评估的条件：浏览器提供可保留路径段语义与末级开头的原生省略组件；产品允许完全隐藏末级目录；或新增终端提示符场景并需要独立的终端列宽适配。终端提示符压缩不属于本决策范围，不应把 DOM 像素测量直接搬进终端缓冲区。
