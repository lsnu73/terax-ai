# 命令块查找输入框的焦点被终端抢回

- 首次出现：2026-11-02
- 影响范围：从终端命令块右键菜单打开「在命令块中查找」的用户
- 复现条件：块搜索框由 `BlockOverlay` 按需挂载，且右键菜单关闭时执行终端焦点恢复

## 表象

点击「在命令块中查找」后，搜索框虽然出现，但光标落在终端下一条命令输入位置，键盘输入进入 Shell 而不是搜索框。Ctrl+F 打开的搜索框没有该问题。

## 根因

`BlockContextMenu` 的 `onCloseAutoFocus` 会调用 `session.focus()`。原块搜索框是另一套延迟挂载的 `BlockOverlay SearchBar`，仅依靠自身挂载 effect 聚焦；菜单的焦点恢复与懒挂载时序叠加后，终端成为最终焦点。两条搜索入口的 UI 和焦点生命周期不同，使 Ctrl+F 已有的聚焦保障没有覆盖块搜索。

## 已采用的修复

删除独立块搜索框，右键入口改为创建 `GhosttyBlockSearchController` 并交给 `App` 的共享 `searchTarget`。Ctrl+F 与块查找都使用已挂载的 `SearchInline`；`App` 收到局部目标后显式调用其 `focus()`。差异只保留在搜索控制器：全文控制器扫描终端，局部控制器只扫描指定块。

## 复发防护

遵守 INV-016：终端搜索入口不得重新在块覆盖层或右键菜单内创建第二套搜索输入框，新搜索范围应适配 `TerminalSearchController` 后接入共享 `SearchInline`。本次按用户要求未运行或新增测试，焦点时序需靠交互代码评审把关。
