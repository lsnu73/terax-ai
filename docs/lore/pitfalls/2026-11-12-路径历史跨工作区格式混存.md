# 路径历史跨工作区格式混存，归一化只能在读取侧

- 首次出现：2026-11-12
- 影响范围：Ctrl+E 最近路径弹窗与命令面板 `>` 模式在 Windows 与 WSL 工作区之间的路径显示与选中
- 复现条件：在 WSL 工作区进入 `/mnt/c/...`（或自定义挂载根）后切回 Windows 工作区打开最近路径，反向同理

## 表象

Windows 工作区的最近路径里出现 `/mnt/c/Users/wang`、`/home/...` 这类 Linux 路径；或 WSL 工作区里看不到任何 Windows 历史路径。若在记录时统一改写格式，则另一侧工作区要么丢历史、要么同一目录出现两条。

## 根因

路径历史是跨工作区共享的单一偏好列表，记录侧保留 shell 上报的原始格式（Windows 工作区记 Windows 格式，WSL 工作区记 Linux 格式）。归一化若发生在记录侧，存储就被某一种格式锁定，另一个工作区的视图无法还原；若按工作区过滤存储，共享历史也会单侧丢失。

## 已采用的修复

读取侧用 `normalizePathHistoryForEnv` 按当前工作区归一化：Windows 视图把挂载根下的单字母盘符段折回 `X:\...` 并隐藏 `/home`、`/dev` 等 Linux 专属目录；WSL 视图给 Windows 盘符路径加当前发行版的挂载前缀；同一目录的两种格式合并为一条（保留最新）。挂载根来自 Rust 命令 `wsl_automount_root`（发行版 `/etc/wsl.conf` 的 `[automount] root`，缺省 `/mnt/`），按发行版缓存在应用运行期内——wsl.conf 的修改要 `wsl --shutdown` 后才生效，运行期缓存恰好覆盖该设置的完整生命周期。Windows 工作区取 `lastWslDistro` 偏好指向的发行版作为自定义挂载根来源，默认 `/mnt/` 恒为候选。

## 复发防护

`pathHistory.test.ts` 锁定两种视图的折算、隐藏与合并；`workspace.rs` 的 `automount_root_*` 测试锁定 wsl.conf 解析与缺省。改动记录逻辑或存储格式时必须两侧同验；不要把「清理存储格式」当成无害重构。
