# WSL Bash 命令块无法复制或重跑
- 首次出现：2026-11-13
- 影响范围：使用 Bash 4.4+ 的 WSL 终端，以及其他使用同一 Bash 集成的 Unix 终端
- 复现条件：执行一条命令并等待提示符恢复，右键该命令块，观察「复制命令」与「重新运行」

## 表象

命令块及其余右键操作存在，但「复制命令」和「重新运行」同时禁用。Windows 本地 PowerShell 的同名故障曾经由全局提示符状态门控引起，本次不是该旧问题复发。

## 根因

Bash 集成的 PS0 原来只发送无载荷的 `OSC 133;C`，所以块控制器能划分命令边界，却得到空 `command` 和 `canRerun === false`，两个菜单项按既有规则禁用。

不能用两个看似简单的捷径修补：

- 实测 PS0 展开时的 `BASH_COMMAND` 是之前执行的命令，复合命令还可能只留下其中一个简单命令，直接使用会复制或重跑错误文本。
- `history 1` 配合 `HISTCMD` 也不能识别陈旧历史。普通输入与被 `HISTCONTROL=ignorespace` 忽略的输入都可能满足 `HISTCMD` 等于最新历史编号加一，但后者的 `history 1` 仍是上一条命令。

## 已采用的修复

`bashrc.bash` 在每次现有 `PROMPT_COMMAND` 完成后记录最新历史编号作为基线。PS0 只接受编号恰好为基线加一的新历史项，清理控制字符并按既有 256 字符上限上报。被 `HISTCONTROL` / `HISTIGNORE` 排除的输入不会产生新历史项，因此发送空载荷而不是旧命令。关闭 `cmdhist` 时可能只剩多行命令的最后一行，也统一 fail closed。未引入 DEBUG trap，用户原有 PS0 与 trap 保持不变。

## 复发防护

`src/modules/terminal/ghostty/shellBlockCompatibility.test.ts` 使用真实交互式 Bash 断言连续命令、带引号命令、`ignorespace`、`HISTIGNORE` 和多行命令清理。WSL 实测还确认普通命令上报当前文本，历史忽略场景上报空载荷。修改 Bash 命令捕获时必须保留这些回归，不能只检查 PS0 含有 `133;C`。
