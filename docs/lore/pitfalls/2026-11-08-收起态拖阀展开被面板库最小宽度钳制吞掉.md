# 收起态拖阀渐进展开被面板库最小宽度钳制吞掉
- 首次出现：2026-11-08（需求开发时读库源码定位）
- 影响范围：所有依赖 `react-resizable-panels` 收起/展开行为的交互——目前是左右边框拖拽阀（侧栏与 AI 面板）
- 复现条件：面板处于收起态（`collapsedSize`），对 `panelRef.resize()` 传入小于 `minSize` 的宽度

## 表象

产品要求收起态拖阀时面板逐像素跟随展开。最初的实现沿用展开态逻辑逐帧调 `panel.resize(px)`，但收起态下拖动距离在约半个最小宽度（110px）以内面板纹丝不动，超过后直接从 0 跳到 220px——用户拖动全程没有连续反馈。

## 根因

`react-resizable-panels` v4 的每帧钳制函数（dist 内 `se()`）对低于 `minSize` 的请求尺寸做三段处理：

- 非收起态：直接钳回 `minSize`；
- 收起态（`prevSize <= collapsedSize`）：与 `collapsedThreshold`（默认 `minSize` 与 `collapsedSize` 距离的一半）比较，低于阈值钳回 `collapsedSize`（0），高于阈值**直接钳到 `minSize`**——不存在「按请求尺寸应用」的分支。

所以收起态下无论 `resize()` 传多少，结果只有 0 或最小宽度两档，渐进展开在库层面被结构性排除。

## 已采用的修复

手势期间临时解除钳制，收尾恢复：

- `src/app/App.tsx`：`sidebarLiveMinSize` / `aiPanelLiveMinSize` 状态驱动两个面板的 `minSize` 属性；`beginDragOpen()` 降为 0，`endDragOpen()` 先按目标宽度（拖动距离补齐到最小宽度）`resize()` 再恢复 `minSize`——恢复时面板已满足约束，钳制重算无跳动；
- `src/app/components/WindowEdgeValves.tsx`：阀的 pointerdown 按相邻面板收起态分流，pointerup 与 pointercancel 共用 `onUp` 保证 begin/end 严格配对；
- 备选方案均不成立：`expand()` 只能展开到上次的 `expandToSize` 或 `minSize`，无法逐像素；`collapsedThreshold` 只影响收/展判定阈值，不影响钳制目标；自绘拖拽 UI 代价远超一个状态位。

## 复发防护

- **INV-020**：minSize 是硬钳制，亚最小宽度展示必须「手势期间降 0 + 收尾恢复 + begin/end 配对」；改阀生命周期或新增亚最小宽度交互时强制核对。
