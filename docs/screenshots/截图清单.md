# README 截图清单

根目录 `README.md` 的“界面截图”一节引用了本目录下的 8 张图片。请把截图保存为 PNG，文件名和路径与下表完全一致。

|---|---|
| `01-overview.png` | 主界面全景：文件树、终端、标签栏、AI 面板、状态栏 |
| `02-terminal.png` | 终端命令与结果块，以及块右键菜单 |
| `03-ai-panel.png` | AI 面板：中文对话、工具审批卡片、模型与审批模式 |
| `04-editor.png` | 编辑器与 AI 编辑差异，逐块接受或拒绝 |

| `08-notifications.png` | 通知中心：代理活动或软件运行消息 |

## 拍摄前统一准备

1. 打开“设置 → 通用 → 语言”，选择“中文”。如果已经是中文，跳过。
2. 选择一个固定的外观主题，建议深色，8 张截图尽量保持一致。
3. 准备一个用于演示的 Git 项目。不要使用包含真实密钥、客户数据、公司内部路径或个人信息的工作区。
4. 把窗口拉到 1440×900 或更大，关闭与截图无关的标签，确保底部状态栏可见。
5. 终端历史可以先清屏再运行演示命令，避免出现无关的命令和路径。
6. 使用 Windows 截图工具（`Win+Shift+S`）或其他工具截取窗口，保存为 PNG。
7. 不要在截图里暴露 API Key、代理软件安装路径、用户名、内网地址或真实项目名。

## 01-overview.png

**目标**：一张能看清整体布局的主界面全景。

1. 在演示项目目录打开一个终端，左侧文件树展开 2 到 3 层。
2. 顶部标签栏保留 2 到 3 个标签，例如“终端”“编辑器”“预览”。
3. 按 `Ctrl+I` 打开右侧 AI 面板，问一个短问题，例如“用三句话介绍这个项目”，保留一段中文问答。
4. AI 面板宽度保持在 380 到 450 像素左右，不要挤掉中间的终端。
5. 确认底部状态栏可见，然后截取整个 Terax 窗口。

## 02-terminal.png

**目标**：展示命令与结果块，以及块右键菜单。

1. 在演示项目目录的终端依次运行：

   ```text
   git status
   git log --oneline -5
   git definitely-not-a-command
   ```

   最后一条命令会失败，块尾应出现红色分隔线和退出码。
2. 用鼠标点击终端空白处，确保当前没有文本选区。有选区时右键会进入“问问 Terax”流程，不会弹出命令块菜单。
3. 右键刚才失败的那条命令块，弹出菜单。菜单包含“重新运行”“复制命令”“复制输出”“复制命令和输出”“附加到 AI 对话”“在命令块中查找”。
4. 截取包含终端、块菜单和底部状态栏的窗口。

## 03-ai-panel.png

**目标**：展示 AI 面板、工具审批卡片和输入区元信息。

1. 确认已经在“设置 → 模型”中配置好一个可用模型。
2. 在 AI 面板输入区下方把执行审批模式切换为“需要我审核”。
3. 按 `Ctrl+I` 打开 AI 面板，发送一条会触发命令的请求，例如“运行 git status，然后用三句话解释输出”。
4. 等 AI 发起工具调用，界面出现“需要审批”的确认卡片，卡片上有“批准”和“拒绝”。先不要点批准。
5. 截取 AI 面板，尽量让输入区下方的角色、审批模式、上下文用量和模型选择器一起入镜。
6. 如果想展示代理徽章，可以先开启终端代理或 AI 会话代理，面板头部会出现“代理中”徽章。

## 04-editor.png

**目标**：展示代码编辑器和 AI 编辑差异。

1. 从左侧文件树双击打开一个演示用的代码文件。
2. 保持执行审批模式为“需要我审核”。
3. 在 AI 面板发送一条安全的修改请求，例如“在这个文件顶部加一行注释，说明这个文件的用途”。
4. AI 请求修改文件时，如果出现审批卡片，点击“在 diff 标签页中审查”打开差异标签页。
5. 截取差异标签页，保留新增/删除行的配色和接受/拒绝按钮。顶部标签栏和代码编辑器尽量一起入镜。
6. 演示文件不要包含真实业务逻辑、密钥或内部注释。

## 05-source-control.png

**目标**：展示源代码管理、AI 生成提交信息和提交图。

1. 准备一个至少有两条分支和若干提交的演示 Git 仓库，这样提交图才能显示轨道和合并线。
2. 修改一个文件，按 `Ctrl+G` 打开源代码管理面板，暂存这个文件。
3. 在提交框右侧点击“生成提交信息”按钮，等待 AI 生成一行 Conventional Commit 信息并填入提交框。
4. 从新建标签菜单打开“Git 图谱”标签，调整布局，让源代码管理面板和提交图同时可见。
5. 截取窗口。提交框里保留 AI 生成的提交信息，但不要真的提交。
6. 如果 AI 没有配置，生成按钮会不可用。先完成模型配置再拍。

## 06-preview.png

**目标**：展示网页预览和常用端口菜单。

1. 在终端启动一个本地演示服务，例如 Vite 项目的 `pnpm dev`，或在一个静态目录运行 `python -m http.server 8000`。
2. 按 `Ctrl+Shift+O` 新建预览标签，输入本地地址，例如 `http://localhost:5173` 或 `http://localhost:8000`。
3. 等页面加载完成，点击地址栏左侧的端口按钮，打开“常用开发服务器端口”菜单。
4. 截取预览页面和展开的端口菜单。菜单里应能看到 Vite、Next.js 等预设。
5. 演示页面不要包含真实账号、内部系统或客户数据。

## 07-settings.png

**目标**：展示设置页的代理分区。

1. 按 `Ctrl+,` 打开设置标签页，点击顶部的“代理”。
2. 代理地址填 `localhost`，端口填 `7890`。
3. 打开“终端”和“AI 会话”两个场景，保留“更新”关闭，用三个开关的不同状态展示它们是独立生效的。
4. “软件路径”可以留空。如果填写了本机真实路径，截图时请打码或裁掉。
5. 截取设置页的代理分区，确保“代理生效场景”和“代理软件”两组都能看到。

## 08-notifications.png

**目标**：展示顶栏通知铃铛展开后的通知中心。

**方式一，使用编码代理（推荐，画面更真实）**

1. 点击标签栏的 `+`，选择“代理”，在启动面板中选择 Claude Code、Codex 等已安装的编码代理，启动 1 到 2 个实例。
2. 等代理运行一段时间，直到出现“需要输入”或“已完成”的通知。
3. 点击顶栏铃铛，展开通知中心。
4. 截取铃铛弹层，保留活跃代理和通知消息。不要暴露代理输出中的密钥、账号或内部路径。

**方式二，使用软件运行消息（不需要安装编码代理）**

1. 打开“设置 → 代理”，把“软件路径”填成一个不存在的路径，例如 `C:\not-exist\proxy.exe`。
2. 打开“自动启动”，并开启任意一个代理场景。Terax 尝试启动代理软件失败后，会向通知中心写入一条“代理软件自动启动失败”的消息。
3. 点击顶栏铃铛，展开通知中心，截取消息列表。
4. 拍完后把“自动启动”关掉，并清空通知，避免以后每次启动都触发失败提示。

如果两种方式都不方便，可以暂时删除 `README.md` 中 `08-notifications.png` 对应的表格行，等以后再补。
